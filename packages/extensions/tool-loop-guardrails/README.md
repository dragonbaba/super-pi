# Tool-loop guardrails

Pi 0.84.x runtime extension that prevents mechanical retries without adding a command or prompt instruction.

- Hashes the complete tool name and typed argument graph with SHA-256, canonical key ordering, and 2,048-code-unit UTF-16LE updates. No complete canonical string, sampled head/tail string, or full-input Buffer is constructed. Accepted input is never truncated: limits (16 Mi code units including keys/name, 262,144 values, depth 128) reject oversized or non-data inputs explicitly. The digest is computed once after preparation and shared by admission checks; `tool_result` consumes the stored key without hashing or serializing input again.
- Classifies failed tool results through its local `failure-classification.ts`. For Bash and PowerShell, validated `details.shellExecution` facts take precedence over diagnostic text; only Agent-produced unstarted results can establish a trusted refusal, and child output cannot impersonate one. Verification command families, timeout/cancellation, exit status, and output/observation failures retain their recorded meaning. Without execution facts, at most 8 KiB of text is classified, including mutation/preflight payloads, script failures, LSP workspace escapes, and structured read-only outcomes; the Windows MSYS paired-backslash check also applies only without execution facts.
- Blocks identical sibling calls in one assistant tool batch before execution; the first call remains authoritative and the batch set resets at `turn_start`. Codemode children are scoped by `parentToolCallId` and blocked only while an identical child is still in flight; the reservation is released at the call's terminal `tool_execution_end`, including calls blocked by a later hook, aborted or vetoed, so a script may repeat a completed check.
- Preflights a safely parsed static leading `cd` target and manifest-dependent npm lifecycle actions before spawn, including Windows MSYS drive paths and explicit `--prefix/-C` targets. Dynamic shell paths remain untouched, as do standalone `npx`, `node --test`, `npm init`, and metadata commands.
- Overrides `read` with Pi's native implementation and retries exactly once only after its exact out-of-range offset error. After any supported text-model read, it asks `mutation-guard-write` to mint a bounded snapshot capability, rewrites editable rows as copyable `LINE#ID|content`, and appends `[Snapshot edit]` only when a stable captured byte buffer exactly reproduces native read's displayed text and line range. Images, unstable files, unsupported text, and mismatched captures remain unannotated. The offset repair reports the actual total line count.
- Overrides `bash` with Pi's native definition while preserving the configured `shellPath`, `shellCommandPrefix`, Session cwd, trust state, SP_* environment, renderers, truncation, abort, and permission hooks. On Windows, only commands containing paired backslashes are removed from argv, capped at 12 KiB UTF-8, carried through a Base64 environment value, and decoded into a nested Bash stdin; the final environment block is preflighted against the 32,767-character CreateProcess limit. Ordinary commands retain native `-c` execution and existing `MSYS` options are untouched.
- Adds bounded cold-path recovery hints for direct `path` inputs and explicit structured `rg` path operands, using the structured tool's own `cwd` rather than the parent Session cwd; also covers Windows MSYS regex parse failures, Windows ESM `file:` URLs, `/tmp` usage, Node script syntax/module resolution, and shell parse failures. Each deterministic hint states the likely cause, a legal next action, and what unchanged retry to avoid; it does not parse arbitrary Bash paths.
- After two same-category deterministic failures for the same tool and complete arguments, appends a hidden `tool-failure-advisory-v1` advisory and blocks the third attempt. Counts survive different parent scripts, unknown custom-tool success, cancellation and intervening categories. A successful leaf `edit`, `write`, `bash` or `powershell` invalidates deterministic failure counts because workspace state may have changed; this lets a repaired test command run again. Calls that dispatched children and `codemode` parent successes do not invalidate other operations. Other successes clear only their own operation. Parent IDs scope sibling deduplication and identify calls that dispatched children; failure/retry budgets remain keyed by the operation itself. Mutation invalidation does not reset transient retry accounting.
- Every completed tool call advances one fixed-cardinality consecutive-chain state. Exactly at counts 3, 5, and 8, it appends a hidden `tool-loop-reminder-v1` custom message with bounded generic guidance; a changed tool or canonical argument projection resets the chain, and count 8 is the final reminder.
- Reminder delivery is advisory only: it neither vetoes execution nor rewrites the authoritative tool result. Raw arguments are absent from reminder content and are not retained in repeat state.
- Parent completion or cancellation clears its pending children and sibling-release metadata. `agent_end` and `agent_start` clear all run-local state, including deterministic failures, retry budgets, duplicate identities and reminders. Cancellation itself does not add a deterministic failure.
- Keeps metadata bounded: 64 deterministic signatures, 64 transient operations, 64 tool summaries, 256 native batch identities, 256 pending invocations, and 4,096 completed sibling identities. IDs are limited to 512 code units, operation keys to 124, repair notes to 1,024, and error inspection to 8,192. Deterministic signatures use FIFO eviction with an explicit counter; evicted or unseen identities are admitted normally. A full retry table preserves its existing operations and reservations. Further unknown identities remain admissible, but their transient failures use one `transient_retry_overflow` deterministic signature with a two-failure threshold, even if a retry slot later becomes free in the same run. Overflow failures are counted explicitly. As with other deterministic signatures, this bounded history can be invalidated by a successful known mutation or forgotten through FIFO eviction. Pending/batch/release capacity still refuses admission instead of silently evicting an in-flight identity, and every capacity refusal identifies the operation. Conservative retained-string bounds are below 11 MiB for all tables combined (UTF-16 accounting, excluding engine map/object overhead); no source argument/result is retained. Hash traversal arrays and ancestor sets are call-owned and released on return/throw, with no pooling.

The guard does not retry failed model strategies or infer arbitrary arguments. Its only internal retry is the deterministic native `read` EOF-offset repair described above. Provider retry remains owned by Pi's existing provider layer.

## Transient tool retries

HTTP 5xx, network failures and timeouts use an independent per-operation budget. The user-selected default is **5 total attempts**, including the first, with **1/2/4/8 second** backoffs and **15 seconds** of cumulative scheduled waiting. The extension delays only a newly requested retry; it never replays a tool on its own. Model-provider retries remain separately owned by the provider layer. Shell execution facts outrank arbitrary diagnostic text, so output containing an HTTP error does not turn a recorded deterministic process failure into a retryable transport failure.

An exhausted budget returns `TRANSIENT_RETRY_EXHAUSTED` with `retryable: false` for the current run. A concurrent reserved retry instead returns `TRANSIENT_RETRY_IN_FLIGHT` with `retryable: true` and asks the caller to await its result.

The extension flag `--tool-transient-retry` accepts a JSON object with `maxAttempts`, `maxWaitMs`, `baseDelayMs`, and `maxDelayMs`. Omitted fields retain defaults. Positive integers are required: at most 20 attempts, 120,000 ms cumulative waiting, and 10,000 ms for either delay field; base delay cannot exceed maximum delay. The delay cap leaves 20 seconds of the standard CLI's 30-second safety-hook deadline for preparation and host overhead. Invalid configuration blocks admission with a configuration error. Configuration is read once at extension startup (session start, or the first agent start for embedded hosts) and retained across session replacement; reload the extension to change CLI configuration. There is no jitter. Scheduled waiting is reserved before yielding; measured elapsed waiting is tracked separately because timer delivery can be late under host load. An abort signal, parent completion/cancellation, or agent end interrupts the single timer and releases its listener and resolver. Simultaneous parents cannot reserve two retries of the same operation. A stale retry's success cannot clear a newer budget, and an ordinary sibling's success cannot clear another invocation's live reservation. Exhaustion reports the attempt/wait limits and asks for recovery in a fresh user run.

## Evidence and known boundary

The full-content identity rejects non-plain objects, enumerable accessor properties, cycles, unsupported non-data values and inputs beyond its 16 Mi code-unit / 262,144-value / depth-128 bounds by throwing `[TOOL_ARGS_INVALID]` before execution. This is an intentional rejection boundary added by the complete-content identity. Ordinary model JSON within those bounds is supported; extensions must supply plain data rather than objects with executable accessors or custom prototypes.

The exact source gate is `tests/tool-loop-repeat-hot-paths.test.ts`; behavior and production hash-scan probes are in `tests/tool-loop-repeat.test.ts`. `node --expose-gc --experimental-strip-types scripts/bench/tool-loop-repeat.ts [independent-checkout]` samples the real extension hook chain and tests source release after normal completion, failure, parent cancellation and preparation cancellation. It is also runnable against an independently installed/built baseline. Full hashing deliberately scans more bytes than the old lossy sample; sampling/CPU results must report that cost rather than claiming equivalent work.

Known limitation accepted for this PR: if a later extension rewrites an ordinary tool's arguments after this hook, its result is recorded against the admission-time key. This module does not mint permission authorization; the existing Shell final authorization still rechecks its input before execution. A follow-up must extend `ToolInvocationAuthorization` and `PendingToolAuthorization.consume` to support generic final parameter validation (`packages/agent/src/types.ts`, `packages/coding-agent/src/core/extensions/runner.ts`, with invocation integration/validation in `packages/agent/src/agent-loop.ts` and extension types as necessary). It needs exact AST coverage for the final-consume chain, once-per-admission scan counters, argument-mutation tests, bounded pre-invocation ownership, cancellation/throw/release tests, and dispatch/session allocation plus controlled-GC evidence. This PR does not modify those shared interfaces. Frozen F-S6 assertions are unchanged. The allowFailure end-to-end R0 cases require PR B; D must merge after B.
