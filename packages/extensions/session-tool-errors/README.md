# Session tool errors

Snapshot LINE#ID edit failures are classified from anchored `[SNAPSHOT_EDIT_*]` codes, including anchor mismatch, boundary echo, syntax regression, stale/unknown/unseen/budget/overlap/no-op/input/unsupported/partial outcomes. Reports retain safe `kind`, `start`, `end`, and bounded `newLines`, but intentionally omit the opaque snapshot capability.

## Command

```text
/tool-errors
```

The command scans `SessionManager.getBranch()` and generates a copyable Markdown report. In TUI mode it first uses Pi's native `copyToClipboard()` utility. If clipboard delivery fails, or the command runs outside TUI mode, it atomically writes and replaces `<current-project>/.super-pi/tool-errors-report.md` and reports that path. It never fills the input editor.
The report includes failed tool results, assistant/provider errors, and failed or cancelled user Bash executions stored on the current active branch. A built-in Bash result is omitted only when its original tool call proves it was one standalone `rg` invocation and the stored result is exactly an empty exit-code-1 response (ripgrep's documented no-match outcome). A bounded linear quote-aware scan allows regex operators such as `|` inside valid single/double-quoted arguments while rejecting shell operators outside quotes, command substitution, unterminated quotes, stderr, other tools, and user `!` Bash. Structured `rg` already returns `no_matches` as a successful tool result. Duplicate errors are grouped and assigned deterministic categories with classification hints. When multiple tool results from one originating assistant tool batch are all aborted, they are collapsed into one causal `tool_batch · aborted` observation with the bounded member count; entry identities remain internal and are never rendered. Mutation Guard failures retain their runtime categories (`read_required`, `stale_state`, ambiguity, no-op edit, budget, target appearance, safe write/edit failure, and partial mutation), including snapshot LINE#ID failure prefixes and bounded leading JSON followed by human-readable diagnostics. Failed `edit` input correlation supports both snapshot `kind/start/end/newLines` and exact `oldText/newText/expectedLine`; opaque snapshot IDs are omitted. Structured read-only command JSON retains command failure/timeout state while still refining missing paths and wrong repository roots. Structured preflight payloads retain `workdir_mismatch`, `platform_path_error`, `duplicate_call`, and `repeated_call_blocked` instead of collapsing into generic runtime errors. Missing required CodeGraph action arguments are input-validation errors. Failed Bash test, typecheck, build, and lint invocations are classified from their originating tool-call command when no more specific error applies. Provider classification includes WebSocket, fetch, terminated, upstream reset, disconnect-before-headers, ECONNRESET, and socket-hang-up failures. Shell parser/quoting/cwd syntax, inner-script syntax and runtime exceptions, missing environment components, policy, encoding, assertions, configuration, platform-path, localized Windows/os-error-2 missing paths, and generic command failures remain distinct. LSP paths outside the selected workspace are `workspace_escape`, invalid server/route/symbol/line/limit requests are `input_validation`, and missing configured LSP commands are `environment_error`; migration targets that are not exact versions are `input_validation`; MSYS rewriting of native `taskkill /PID|/T|/F` switches and the bounded `[MSYS argv recovery]` marker for paired-backslash regex corruption are `platform_path_error`; the model Bash path uses the bounded stdin bridge rather than unsafe `MSYS=noglob`, and an oversized bridged Windows environment is `environment_error`. Consecutive retryable provider failures are followed through their direct assistant parent chain so an eventual successful automatic retry is reported as recovery rather than as a missing tool retry. For each failure, the extension follows the session parent chain to the direct next assistant message and includes its stored `thinking` blocks as post-error model reasoning when present; it never substitutes later unrelated reasoning or generated analysis. Reasoning is labeled as model self-diagnosis only when explicit causal or self-correction wording is present, otherwise the report states that it is not asserted as the cause. The report also records whether directly following tool calls succeeded, failed, had mixed results, or were not recorded.

Each grouped raw error keeps at most 12,000 characters (the first 8,000 and last 4,000) with an explicit omitted-character count; the complete source remains in the current session. Formatting considers at most the latest 512 observations and emits at most 48 detail groups, 24 categories, and 8 groups per category. The complete Markdown report is capped at 96 KiB UTF-8, includes deterministic omission counts when space permits, and delivery independently rejects any oversized report. Bounded reports are copied in TUI mode; clipboard failure or non-TUI mode uses the one fixed project-local file. The extension has no background hooks, counters, timers, persistent telemetry, or nested model calls. It never serializes Bash commands or non-edit tool arguments. ANSI/control sequences and common authorization, token, API-key, secret, and password forms are redacted before delivery. The fallback refuses a symlinked or escaping project config directory and removes its atomic-write staging file.
