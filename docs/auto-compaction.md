# 自动压缩百分比

自动压缩默认在上下文占用达到 **85%** 时触发。使用 `/autocompact`
或 `/autocompact status` 查看当前供应商、模型、百分比、有效上下文容量、
对应 token 阈值和自动压缩开关。修改示例：

```text
/autocompact 90%
/autocompact 70
/autocompact 85.5%
```

`/settings` 的 **Auto-compact percentage** 是文本输入，可填写 1–100
之间的百分比，支持小数和可选的 `%`。非法输入不修改原值，Esc 取消。
**Auto-compact** 开关独立控制是否自动压缩；修改百分比不会打开该开关，
也不会立即发起压缩、发送模型请求或重跑工具。

## 保存与模型容量

每个“供应商 ID + 模型 ID”独立保存百分比。切换供应商、模型、重载或重启
不会重写已保存值；未设置的组合使用 85%。同名模型由不同供应商提供时，
可以分别使用不同百分比。上下文容量更新时只重新计算 token 阈值，不改写
百分比。

设置保存在全局 `~/.sp/agent/config/settings.json` 的
`modelAutoCompactionPercentages` 对象，键是
`encodeURIComponent(provider) + '/' + encodeURIComponent(modelId)`。
例如供应商 `example` 的模型 `family/model` 使用键 `example/family%2Fmodel`。
通常直接使用命令或设置菜单，无需手写键。项目设置不能覆盖这个用户偏好。
SDK 可以调用 `session.setAutoCompactionPercentage(number)`，会等待保存结果，
写入错误会向调用者报告。

容量采用当前模型注册表已经解析出的 `contextWindow`，包括该供应商的
自定义模型配置。不使用其他供应商的容量、不猜测额外推荐值，也不为检测容量
发送探测请求。子代理按其实际选择的供应商、模型和全局设置解析自己的阈值。

阈值统一为 `floor(contextWindow × percentage / 100)`，达到阈值即具备正常
自动压缩的用量条件。例如默认 85%：

| 有效上下文容量 | 自动压缩阈值 |
| ---: | ---: |
| 131072 | 111411 tokens |
| 337673 | 287022 tokens |
| 500000 | 425000 tokens |

## 运行边界与显示

提示前、工具批次后下一请求前、助手结束时的正常自动检查、工具结果裁剪
可行性和压缩记账使用同一计算函数。状态栏直接读取会话引擎提供的阈值，
原生 footer 显示当前百分比。旧宿主若不提供该阈值，扩展状态栏省略推测性的
pending 标记。显示百分比不会改变模型可见的系统提示或工具定义。

`compaction.reserveTokens` 继续作为摘要/请求准备的额度，不再隐含第二个
自动触发阈值。实际模型输入/输出额度、供应商限制、VM 资源、协议、权限和
取消边界仍然适用。百分比不是一次请求必定容纳所有历史和输出的保证。

已付费但未提交压缩边界时仍阻止自动续跑；失败或未验证的历史用量不会冒充
新请求的有效用量。刚压缩后的物化检查点如果本身仍达到阈值，不立即循环
压缩。现有供应商溢出恢复与取消规则保持独立，成功工具绝不自动重放。
