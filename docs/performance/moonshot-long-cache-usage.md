# Moonshot K3 1-hour cache-write usage

Baseline: `1257a336fdbee6f97e0aa60e5a706fd4cae0501e` (PR #99 merged).
Verified on Windows / Node 26.4.0, 2026-10-11 JST.

## Contract and scope

The official [international guide](https://platform.kimi.ai/docs/guide/context-caching)
and [China guide](https://platform.kimi.com/docs/guide/context-caching) specify
disjoint ordinary input, cache reads and cache writes. The response header
`Msh-Usage-Cache-Write-Tokens-1h` reports actual long writes; body usage reports
total writes. TTL locks at the initial write, so request `prompt_cache_options`
cannot establish the billed split. The existing cost calculator already prices
the `cacheWrite1h` subset at twice the selected input rate.

The Chat Completions adapter now reads that header once, after a successful
request/retry and before the optional response hook. Only `kimi-k3` belonging to
`moonshotai` or `moonshotai-cn` opts in. A nonempty decimal safe integer is kept
as a request-local primitive. Other providers/models never read this header.
Negative, fractional, nonnumeric, combined duplicate and unsafe values are
ignored. Native `Headers` supplies case-insensitive lookup and trims HTTP OWS.

Both `chunk.usage` and the existing `choice.usage` fallback receive the primitive.
It is bounded by nonnegative body cache writes and stored in the existing optional
`cacheWrite1h` field. Cumulative/repeated usage replaces the estimate, rather than
adding the header count repeatedly. Input, total cache writes and total tokens
retain their existing values. No body writes means no invented writes. Missing
or invalid headers preserve the previous default-write estimate; they cannot
provide accurate long-write billing. An undefined optional slot is omitted by JSON
serialization. Request TTL behavior, catalogs, currency conventions, custom
provider aliases, reseller/subscription policies and other API adapters are outside
this change. Explicit rates, selected context tiers and unknown-price handling
still use the existing calculator.

## Full production chain and ownership audit

Built-in provider / `createProvider` dispatch → `lazyApi` / `lazyStream` → optional
`streamSimple` / `buildBaseOptions` → `stream`, capability context, payload/client
construction and `onPayload` → `retryProviderRequest` / SDK `withResponse` → header
primitive → SDK SSE decoding → both usage paths / `parseChunkUsage` →
`calculateCost` → assistant partial/final event → `EventStream` queue and lazy
forwarder → consumer or `.result()` → caller release. The Models facade adds the
existing auth/lazy boundary before this chain. Session usage totals and cache
statistics consume the computed cost directly; both compaction implementations
already sum the optional long-write subset. These consumers need no new wrappers.

The new state is one number or undefined per request. Header text lives only for
the synchronous parser call. There is no new retained Response/Headers reference,
event, body copy, timer, listener, Promise, controller, closure, array, object pool
or mutable global cache. Lookup/decimal validation run once per response; each
usage update adds only a conditional and min/max arithmetic in the existing
usage literal. Owned usage/cost results remain externally visible message data,
never scratch or pooled objects.

Existing allocations remain explicit: two usage/cost objects per usage update;
one fallback empty tier array in `calculateCost` when tiers are absent; event
records and a reasoning-field array in delta handling; content/tool blocks and
request maps/closures; SDK parsing and asynchronous iterator/waiter Promises;
request setup/options and optional response-hook header records. Event queues own
pending events until consumed or the stream is released; a retained result Promise
intentionally owns its final message. This patch does not certify the legacy
pipeline as allocation-free or impose a new queue capacity. No terminal frame
is generated by the header parser, and it copies no full-size strings/bodies.

The benchmark reverses only the new helper, its one boundary call, the two
primitive arguments and the usage field, then compares the entire adapter AST
with the baseline. All other production-file changes are comments; calculator
and type ASTs remain identical. This includes unchanged delta delivery, retry,
completion/error/abort cleanup and downstream production functions.

Allocation counters instrument the real production functions, including the cost
helper; they count executed application allocation sites, not VM/SDK/native
`Headers` bytes. No throughput or bytes-per-event improvement is claimed. The
`--baseline` mode transpiles the recorded adapter into a task-owned `.git` evidence
file and uses the same provider/lazy wrappers, transports and observer as the
candidate. It makes no production checkout changes.

The failure retention is pre-existing: the SDK aborts its internal controller in
stream cleanup, its signal can hold a lazy `AbortError` stack, and the caller's
signal still owns the SDK forwarding callback. The probe separately observes that
reading the SDK reason's stack releases the frame references in both revisions.
It does not silently change production cleanup or claim unconditional error-path
release. Caller abort uses a primitive reason to distinguish this SDK boundary
from caller-owned error stacks. The probe checks contexts, payload/messages,
options, streams, results/usage, response/body/headers and body controllers.
It uses synthetic credentials and mock transports; no live inference or billing
acceptance is performed. The new primitive adds no reference to this existing
retention chain.
