# Phase 5B-B budgeted tool-result model view

Phase 5B-B adds an opt-in `ToolResultPresentationV2` at the final, post-extension tool-result boundary. It requires both `enabled: true` and an explicit positive `budgetTokens`. The default, absent, disabled, and enabled-without-budget paths retain Phase 5B-A/V1 behavior: the provider receives the legacy content unchanged and no continuation is created. This phase does not select a production default budget.

## Ownership and production chain

The persisted `ToolResultMessage.content` remains the complete post-extension result and is the UI source of truth. A V2 presentation owns an independent UI outer array whose text/image blocks and underlying strings are immutable references to that complete result. Truncation never writes into the legacy message or an extension-visible event.

The coding-agent SDK applies provider-neutral projection to the complete persisted source before the existing image-input policy. Image blocking then operates only on bounded `modelContent`; a fixed-pass bounded recheck shrinks placeholder text when necessary without rescanning the complete source. If an initially V1-sized source exceeds its budget only after image placeholders are inserted, the source record creates a real V2 full-omission projection with the fixed internal notice and a continuation cursor. Notice ownership is record identity, never a prefix/suffix match against user text. Only the bounded view is placed in the provider message wrapper; image data, `uiContent`, presentation metadata, and continuation state do not enter the provider wire. Provider adapters are unchanged.

The projection is reproducible from the persisted full message, session identity, tool-call identity, explicit budget, fixed algorithm version, and estimator metadata. A session-local, hard-cap projection/source index avoids repeated full scans while retaining at most 128 entries and 128 Mi UTF-16 code units. Final-result and continuation admissions may evict under that unified capacity; provider-read misses cannot evict resident hot records. Overflow provider reads use transient no-admit projections, so a sequential scan of 129 or 256 results cannot cascade into eviction of all 128 residents. An evicted result admitted for an active continuation chain remains bounded by the same capacity and serves later pages without another transcript or full-source scan. The index is not a global `WeakMap` and is cleared on permanent context replacement, branch switch, new-session owner replacement, and dispose. Resume lazily indexes the matching active-branch source once.

Cursor identity contains bounded session/tool identity plus a bounded SHA-256 content digest produced by streaming the existing block strings without joining, serializing, or copying the complete result. The digest never enters telemetry. Same-metrics changed content, missing/switched sources, and duplicate source identity fail explicitly as stale or ambiguous.

## Projection algorithm

Oversized text is represented by deterministic bounded head and tail slices separated by a fixed truncation notice containing the continuation cursor. First projection performs one full estimator scan, one streaming digest pass, and at most four bounded re-estimation/shrink passes. Later provider preparations and continuation chunks reuse the session record. It does not split into lines, serialize the complete result, copy image data, or create another full-size string. Multiple text blocks preserve source order; image blocks remain represented structurally without charging image-token cost to the text estimator.

Candidate cuts retain the printable-ASCII direct path. Non-ASCII cuts use one module-level grapheme segmenter only at a fixed number of boundaries. The one-time source scan builds a record-owned, fixed-capacity flat `Uint32Array` of terminal-sequence block/start/end intervals; boundary lookups use direct indexing and binary search, so continuation pages do not repeatedly scan the consumed prefix. CSI, OSC, APC/DCS/PM, and incomplete control sequences remain atomic. If the interval capacity is exhausted or a bounded request cannot prove one atomic grapheme or terminal boundary, projection conservatively falls back to a text-block boundary or fails explicitly instead of cutting the structure.

Every truncated result has a resumable continuation descriptor. Continuation reads return bounded text chunks in source order, use the same token estimator, and report whether more content remains. Budgets too small to hold the fixed notice fail explicitly. V1 remains unchanged and unknown/malformed presentation versions conservatively fall back to the legacy message.

## Correctness coverage

Tests cover absent/disabled/invalid budgets, small V1 results, English, CJK, JSON, source code, long CSI, OSC 8 BEL/ST, APC/DCS/PM, incomplete terminal sequences, emoji modifiers/families/flags/keycaps/tags, 64/256 combining marks, variation selectors, malformed surrogate boundaries, a 10 MiB single line, multiple blocks, and text plus image. They also cover exact continuation reconstruction, resumed-session projection identity, same-metrics changed-source rejection, duplicate identity, 20 repeated provider requests, 1/10/100/129/256 historical results, retained-code-unit capacity overflow, 100 continuation chunks over 50k history, evicted-record continuation, cache capacity/clear, V1 image-only/interleaved/consecutive-image expansion, forged notice-like user text, block-image toggles, provider-wire isolation, extension/session-event isolation, full legacy persistence, and strict malformed-V2 fallback.

Transcript validation does not retain an old transcript outer array strongly. Each record keeps a weak array reference plus primitive validated length/source index and the source message reference. Ordinary append checks the source slot in O(1) and scans only the appended tail; duplicate identities, source-slot replacement, shrink, and reorder fail stale or trigger conservative revalidation. Context replacement and disposal clear all validation state.

The ownership fixtures prove that model/UI outer arrays are distinct, complete UI block references are reused, text and image-data string identities are reused, and provider projection does not mutate the legacy message. Parallel direct-owner fixtures exercise 2, 4, and 8 active dispatch scopes; high-water marks are exactly 2, 4, and 8, all active scopes return to zero after matching release, disposal does not synthesize releases, and listener-retained presentations remain readable.

## Performance method

`npm run bench:tool-result-budgeted-model-view` uses five warmups, twenty measured operations, a 1,024-byte HeapProfiler sampling interval, controlled GC, and top-20 sampled allocation sites. Direct fixtures are tiny, 64 KiB, 1 MiB, 10 MiB, multi-block, text plus image, and ANSI/grapheme adversarial input. Production fixtures use the actual AgentSession final-result chain in absent, disabled, enabled, V1-placeholder expansion, and image-policy toggle modes. The image-policy evidence distinguishes the persisted presentation cursor from the wider provider cursor produced when post-policy fitting drops additional source units, then proves that wider cursor is accepted against the persisted source and remains within budget. Separate fixtures measure first versus steady projection; 1/10/100/129/256 historical results; retained-code-unit overflow; current/resumed projection; 100-page normal and evicted-record continuations; 50k-history lookup; 1/10 MiB ANSI and CJK offset scaling; dense terminal logs; combining/ZWJ/flag/keycap/tag boundaries; 2/4/8 scope lifecycles; and WeakRefs for the validation array, source, presentation, both presentation outer arrays, and provider-cloned message/source arrays. The lifecycle fixture clears records before provider projection, proves the clone remains transient, validates and binds the unique persisted source once, proves the next chunk uses resident/indexed hits, then clears/disposes and checks all clone and validation WeakRefs. The 10 MiB digest fixture separately reports `heapUsed`, `external`, and `arrayBuffers` peak/delta to expose any allocation outside the sampled JavaScript heap.

## Limits retained for later phases

This phase does not choose a default budget, summarize output, create artifacts, add a continuation UI, alter TUI rendering, or enforce remaining-context policy. Text estimation excludes image billing/tokens. The cursor retains only a bounded source key/digest and positions; complete source/model references live only in the hard-cap session record and are cleared with its lifecycle. Provider-specific exact estimators and budget safety factors remain Phase 5A extension points rather than provider-adapter truncation logic.
