## 行为与边界

用户报告的固定三个 JSON 文件循环被生产扫描器判为高风险：`< "$f"`
触发 `unverifiable_redirection`，权限控制器因此在授权前返回 `DYNAMIC_TARGET`；
`tr` 还会被单独归为 opaque command。`full-access` 原本只放宽路径范围，
不会放宽无法确认的脚本。用户本轮明确选择修复误拦截、保留危险操作检查。

新增有界只读模式识别，支持固定文件列表、`echo` 标签、`cat`/`tr` 的循环变量
输入重定向；只提交原始命令执行，不改写命令或传播一般变量状态。
上限为 4096 字符、256 个词、16 个文件、32 个命令，变量只允许小写本地名称，
排除 `_`、`path`、`cdpath`、`fpath`。完整模式判断保留词的引号信息；特别是引号内
的分号不能吞掉后面的真实分隔符。此前宣称“额外命令均回落”不成立；这段描述仅
适用于分隔符修复后的候选。未匹配的命令继续走原扫描器。独立 `tr` 归入只读命令，
重定向仍另行审查。

默认卡片所有子调用统一显示摘要，成功输出、脚本返回值、共享输出和结果文件路径
均在展开后显示，最后一项没有特殊待遇。必要错误统一为最多 320 字符的单段摘要
（截断标记另占 1 字符，窄终端自然换行），命令摘要最多 96 字符。
与失败子项匹配的 `[CODEMODE_SCRIPT] [ref]` 包装错误只在展开时显示；独立
脚本错误以 `Script error:` 标明归属。确认全部子项 `not_executed` 时，不显示
未知退出码、零耗时和副作用不回滚警告。执行过或状态不明的失败仍保留警告。
展开保留原有完整诊断及显示上限；模型结果、会话记录、读凭据和失败传播不变。

## 调用链与分配

审计链：Agent 子事件 → AgentSession → InteractiveMode.handleEvent →
ToolExecutionComponent.startNestedTool/updateNestedTool → CodemodeTreeComponent
及行组件 → Text/Container → retained transcript → TUI frame/terminal queue →
releaseComponentRenderCaches。结果完成与历史恢复另经 updateParent/projectResult。
策略识别位于低频 PermissionController 请求检查边界，不进入进度、帧或读取证据查找。

正常进度没有新增闭包、Promise、AbortController、包装对象或数组；正则和限制
放在模块内，没有 String 构造函数、动态正则或对象池。行组件保留原有预览和标签
缓存；只增加布尔状态。父卡片仅在失败时生成至多 321 字符的紧凑预览，完成时计算，展开
切换不重新解析结果。拼接预览前先裁剪输入，避免为预览复制整段大结果。
旧有摘要 hash/输出归属 Map 仍只在完成边界计算；错误包装匹配仅在该边界发生。
只读循环的词数组归属单次检查，有 256 项硬上限，退出即释放；非循环快速退出。

真实事件/渲染基准每组 256 次预热、4096 次更新。折叠基线/候选采样分配为
3956.90 / 3847.30 bytes/update，p95 为 0.0055 / 0.0057 ms。展开首轮为
703095.53 / 702104.79 bytes/update，p95 为 0.5117 / 0.5662 ms；单次计时不足以
声称加速或稳定退化，另做交替基线/候选对照。主要分配点仍是既有 Text 长词换行
和 ANSI 分词，未扩大到本批修改。

追加 3 轮交替顺序对照后，展开 p95：基线 0.5580 / 0.5142 / 0.4982 ms，
候选 0.5032 / 0.4970 / 0.5166 ms；中位数为 0.5142 / 0.5032 ms。
采样分配中位数为 703252.29 / 703563.11 bytes/update（约 +0.04%）。
结果未显示稳定退化，也不作为加速结论。对照期间只临时替换本任务改动的树组件，
每次校验文件身份，finally 原字节恢复最终候选；构建产物和其他生产文件未替换。

两种模式都只创建 1 个树行，4352 次进度更新、4352 次有界预览实体化，进度中
结果投影为 0、结果引用为 0、事件 Promise 为 0。折叠标签实体化 1 次；展开
候选多 1 次显式展开切换时的标签重建，后续更新不反复生成标签。完成及销毁后
行、计时器、结果引用、文本字符数全部归零；受控 GC 后 2 个 WeakRef 全部释放。
失败、取消、挂起/恢复、历史重建的释放与布局由回归测试覆盖。

## 引号分隔符权限绕过修复（2026-10-06）

根因是分词器按前一词的 `value === ";"` 合并分隔符，未核对 `quote`。
`echo ";"; rm -rf data` 被误看作一次 echo 的参数，权限分类与高风险分类均提前
返回“只读/无高风险”。用户给出的三种变体已用当前源码复现；普通未夹带分号的
删除命令对照被识别为高风险。删除命令只用于静态扫描，没有实际执行。

修复让分隔符合并和开头跳过均通过 `keyword(word, ";")` 判断；引号内分号保持
数据身份。新增模块级集合排除 `_` 与三个其他 shell 的查找变量，不新增每次调用
集合、闭包或动态正则。边界仍按 Bash 建模，不声称支持 zsh。扫描处于请求授权
边界，本轮未改动进度、结果投影或 TUI 热路径。

新增三项回归，修复前全部失败、修复后通过：

- 双/单引号 × 四种分隔形式 × echo/cat 两种前置命令，共 16 个隐藏删除命令
  变体，同时检查识别器、权限分类、高风险原语；另有 8 个只读正向对照。
- 真实 Agent/Guard/Bash 夹具在 read-only、workspace-write、full-access 下，
  24 个夹带 `touch .git/config` 的请求均在审批和 spawn 前拒绝；24 个只打印
  分号并读取文件的对照仍原样执行。修复前在隔离临时目录中复现到错误启动；
  夹具在断言失败路径也登记并清理，仅操作本轮自建目录。
