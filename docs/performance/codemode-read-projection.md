# Codemode 多读取结果投影修复

基线：`75559ac2000295442ce8985b89c7a07a81ada8d9`。验证环境：Windows / PowerShell，Node 26.4.0。分支：`codex/codemode-read-projection`。

## 问题与边界

原生读取成功后，`tool-loop-guardrails` 添加成对的 `lines` / `metadata` 标记；Codemode 的 `show(ref)` 将多个子结果按展示顺序放进一个父结果。旧投影器只允许一组标记，第二组触发 `invalid-read-layout`。父结果已经保存，后续用户请求在模型发送前再次扫描它，因此“继续”和重开会话都无法绕过这条历史。

修复接受顺序排列的完整读取组，仍拒绝未配对、组内重复和逆序标记。单组读取继续按完整源代码行与完整元数据裁剪。多组读取在预算不足时向外扩展既有的头尾省略区间，完整保留或省略每一组，不交叉拼接快照。原始内容、顺序及凭据不重写。

Codemode 的独立脚本输出上限也必须保持配对。遇到装不下的读取组，省略该组和后续文本，保留后续图片，并沿用已有的有界落盘与恢复提示。取舍是大读取可能比原来的字符截断少显示一段预览，需要用 `offset/limit` 缩小范围；不会把部分行或未展示的读取认定为编辑依据。历史 continuation、artifact 仍不能替代新鲜读取。

## 完整调用链与分配审计

审计范围：原生 read / 快照签发 → `tool_result` → 嵌套派发 → `CodemodeController.invoke/show/execute` → `capCodemodeOutput` → 保存父结果 → SDK 请求转换 → `AgentSession.projectToolResultMessagesForModel` → `scanSource/buildProjection` → Codemode 展示证据确认 → continuation/artifact → owner release / clear / dispose。

- 快照、子调用和 `show` 沿用现有内容引用，签发与编辑校验未修改。投影在去掉传输标记前通过同步 observer 告知现有 Codemode owner 保留了哪些块，以原位置及块引用确认完整原生读取的新位置，再核对最终展示文本。不会用相同文本的脚本副本替代被省略的原生读取。
- 已有 source scan 多维护一个临时布尔值和组计数，扫描记录新增一个数字字段。投影本就分配的两个区间位置对象由新函数原地调整，不新增组对象、数组或长期索引。只有多组实际裁剪时才扫描块边界；每次构建最多一遍，沿用最多四轮缩减和既有恢复后备路径，不重新复制或散列完整源文本。
- 脚本输出 cap 沿用一个 scratch 文本块与单元素估算数组。组内逐块计算预算，超预算即停止估算；不为每组创建容器。完整组直接复用块引用。没有新增热路径闭包、Promise、AbortController、动态正则、`String()` 或对象池。
- 既有开销保留：source scan 的估算和摘要、投影记录、输出数组、cursor / notice，以及普通文本截断时的有界字符串；脚本溢出仍使用 `OutputAccumulator` 的分块写入和关闭逻辑，落盘上限不变。
- source / Codemode AST 不变量验证上述约束。生产状态与预算关闭/开启三种模式的现有确定性计数，与基线逐字段一致。
- observer 直接传入现有 controller，不创建回调、容器或副本，也不由投影 owner 保留。每条现有读取记录仅增加一个数字位置，沿用最多 16 个待确认父结果、每父结果最多 64 次展示、256 个展示块的边界；只在请求投影时查找引用，不扫描源文本。已显示证据确认、清空、取消与 dispose 继续使用既有释放边界。

## 分配与生命周期证据

基线通过只替换两个生产模块的加载器读取上述 Git 提交，不回退工作树；源码 SHA-256 单独记录。候选使用最终工作树，基准顺序运行。`bench:tool-result-budgeted-model-view` 每项预热 5 次、采样 20 次，HeapProfiler 间隔 1024 bytes。

| 场景 | 基线 / 候选采样 bytes/result | 基线 / 候选 CPU p95 ms |
| --- | --- | --- |
| 64 KiB 直接投影 | 7,424 / 7,345.2 | 1.058 / 1.126 |
| 1 MiB 直接投影 | 7,414.4 / 7,738 | 15.635 / 15.713 |
| 10 MiB 直接投影 | 7,374.8 / 7,492.4 | 152.763 / 154.459 |
| provider 投影 | 6,611.6 / 6,756 | 218.318 / 217.089 |
| 生产会话，预算开启 | 9,747.2 / 9,639.2 | 218.982 / 213.342 |

这些是一次同机对照，不据采样波动宣称提速。主要分配仍来自投影结果、cursor、估算状态和摘要。旧代码无法处理多组读取，不能把失败路径当作多组成功处理的性能基线。

新增多组生命周期用例：48 组 / 16 个结果，源扫描和摘要均为 16 次；重复投影命中 48 次，仅构建 16 个投影数组。最终专项运行中投影模块采样 76,448 bytes；受控 GC 后所有该用例 WeakRef 均释放，记录数与保留字符计数归零。普通 lifecycle 基准的源、展示、模型/UI 数组和校验引用均为零。artifact 子基准在两版都保留 1 个描述符引用，其函数局部 `const artifactDescriptor` 仍在作用域中；不能把该指标写成全部归零，其他源/读取引用和 owner 记录均已释放。

## 正确性与恢复证据

- 新增八项行为/生命周期回归在基线全部失败，候选全部通过；另加一项 cap 的 AST 分配约束，共新增九项，复用既有测试文件。
- PR #69 首次审查的两个边界已独立复现：头部省略后，完整尾部读取移位导致编辑误报 `READ_REQUIRED`；极小预算错误接受了超限恢复提示。两项新回归在首个提交 `be0899d92` 失败，修复后通过。另加两个保护用例：打印的完整文本副本不能替代被省略的原生读取；开启展示但未设预算时仍使用原位置。这一轮共增加四项，并扩展既有 AST 检查覆盖完整映射链。
- 真实完整默认扩展包覆盖两个文件、重复展示同一引用、同一文件两个范围、五文件共享预算、失败后继续和 `SessionManager.open` 重开。恢复不重放读取，不修改已保存的父结果。
- 五文件用例确认：被省略的读取不能用于编辑；重新读取目标范围后，编辑成功。独立 cap 用例覆盖元数据将被切断的边界、完整组引用、后续图片、预算和落盘内容，并按已登记路径删除自己的 spill。
- 多组 continuation 恢复的恰好是被省略的原始区间，无丢失或重复；返回内容去掉读取标记，artifact 仍引用原始内容。原有畸形 hook 布局、单读取裁剪及预算不足恢复测试继续通过。
- 对真实受影响的已保存父结果仅做只读投影：预算 256 / 512 / 8,000 / 16,000，实际估算 139 / 441 / 8,000 / 8,000，均成功。会话文件 SHA-256 前后相同；不把私人会话内容放进测试或 PR。
