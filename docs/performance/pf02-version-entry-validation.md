## 成本与边界

R/S：旧正式 source launcher 为 `--version` 解析完整参数并注入捆绑资源，CLI 再静态加载 HTTP dispatcher 和 main 的完整依赖图；main 创建 settings、处理 auth/package/config 分支后才输出版本。版本查询因而加载交互、包管理、导出和运行时模块，Windows 首次查询还可能建立默认设置文件。

本项调用链为 source launcher 的 dist/捆绑资源校验 → 版本查询识别 → CLI 元数据 → 输出并退出；非独立版本调用仍经 dispatcher → main → 原有 parser/settings/命令处理 → 原有模式初始化。修改不进入 provider delta、TUI 帧、工具进度或运行时关闭热路径。

- 唯一共享识别函数只接受至少一个 `--version` / `-v`，其余 token 只能是 `--offline`；空参数、`--`、选项值、混合帮助、命令或消息均回到完整解析器，不复制整个 CLI parser。
- 正式 source launcher 仍先检查 dist，仍读取并校验全部默认捆绑资源；只不向纯版本查询注入无用的资源参数。损坏 bundle JSON、缺失 extension 等错误继续发生。
- 纯版本查询只输出包元数据，沿用退出码 0 和显式退出语义，不初始化用户 settings/trust/runtime，不修复损坏配置，也不执行更新隔离目录清理。该初始化副作用的移除是先行兼容性决定；有效/缺失/损坏用户配置不应改变包版本。
- `--version --help`、无效 execution environment、auth/package 参数、显式扩展帮助保留完整入口。测试中的 auth/package 分流只拦截 main 验证传参，不触发真实认证或安装。

新识别函数只使用布尔值和字符串比较，没有正则、闭包、对象池或缓存。CLI 的动态导入属于一次启动边界，未把 Promise 移入逐事件路径；原有 warning 回调仍只在入口创建一次。模块缓存由进程持有，版本查询完成后整个进程退出，不增加跨会话保留引用。

## 检测协议与已观察结果

任务根 `.task-tmp/pf02-version-IXcCi5`，所有测试/探针/子进程环境隔离 HOME、配置和 TMP/TEMP/TMPDIR。基线保存原始 launcher、已构建 CLI 和源码，快照只重定位 launcher 根目录、源入口环境路径、最终 CLI 导入及 CLI 的三个相对依赖到同一仓库；其余依赖与候选相同。变换和原始文件将随验收证据归档，不能把该快照当作另一份完整安装。

- 主计时：五组交替驱动进程，每侧每组 2 次预热、6 个正式独立 CLI 子进程，共每侧 30 正式样本、10 预热。每个样本新 HOME；CLI 本身没有预加载或 instrumentation。驱动内另外启动匹配环境的子进程验证临时目录，校验耗时不计入样本；被计量子进程继承相同临时目录变量。这是进程/模块冷启动，未清空 OS 磁盘缓存。
- 已观察版本查询 p50 为 498.06 → 48.58 ms，p95 为 524.04 → 61.16 ms，下降约 88.3%。基线五组 p95 相对带为 4.02%；候选为 17.15%，保留所有慢样本。最慢候选组 p95 为 63.63 ms，相对最小基线组 507.08 ms 仍有明显收益，不能把候选短路径的波动隐藏为稳定微秒指标。
- 独立分配探针使用 HeapProfiler 4096-byte 采样并保留已 GC 样本，加载记录与计时分开。五组基线均为 1848 条加载记录，候选均为 27 条；这包括 Node/CJS/ESM loader 记录，不称为 1848 个唯一业务模块。候选不加载 main、完整 args、SettingsManager、HTTP dispatcher、undici 或 TUI。退出前活动资源列表均为空；完整进程关闭是本项释放边界。
- 非目标对照复用 PF00 的正式 source launcher、管道 TTY、输入命令 ACK、退出和终端恢复夹具，串行交替 baseline/candidate，涵盖 minimal/bundled × regular/fullscreen，每组 2 预热、30 正式样本。该路径需要已有 TTY 适配预加载；与上面的无预加载版本查询分开解释，原生终端体验仍在 PF08。

五组分配探针的采样字节中位数为 124,796,968 → 1,525,512，约下降 98.8%；启动探针初始堆到退出前受控 GC 后堆的差值中位数为 34,011,800 → 653,240 bytes。采样区间从探针准备完成到入口退出，未覆盖 Node 自身及探针初始化；URL 记录等探针成本在两侧同样存在。加载记录不是唯一模块数，采样分配也不等于存活堆。十个进程退出前活动资源列表均为空，随后真实进程关闭；这里的引用释放边界是进程退出，不能外推为长期交互模式的堆斜率结论。

稳定性复核没有把噪声“跑掉”：第二组的六事件分组基线带为 14.03%。六事件 p95 等于样本最大值，因此保留前两组，再补三个独立 30 事件窗口；五个窗口每侧累计 150 个正式事件。基线窗口 p95 为 96.19 / 106.40 / 99.17 / 100.63 / 105.56 ms，候选为 98.49 / 100.21 / 103.17 / 104.43 / 102.43 ms，所有配对增幅均低于 5%（−5.83% 至 +4.03%），没有观察到重复超门限回退。基线窗口 p95 带仍为 **10.151%**，不能四舍五入成“稳定性通过”；窗口 p95 中位数为 100.63 → 102.43 ms，合并 150 个单次事件的 p95 则为 104.15 → 101.68 ms，不据此宣称关闭提速或退化。

随后停止同类重复计时，按证据优先调试流程记录假设并加入任务专用分段探针，各侧 12 正式事件、2 预热。原有 50 ms input drain 实际范围为基线 50.40–62.83 / 候选 50.28–63.92 ms，UI stop 为 1.50–4.96 / 1.51–4.80 ms，runtime dispose 为 2.57–13.39 / 2.53–11.42 ms；退出标记到 close 为 21.97–24.29 / 22.68–24.31 ms，exit 事件到 close 小于 0.024 ms。直接观察到两侧既有等待和释放耗时的波动，不能把总时延尾部归因于入口修改。探针改变导入顺序，其启动时间不作正式启动证据；没有改变产品等待、清理、timeout、OS 优先级或时钟分辨率。绝对关闭计时保持 V，交由 PF07 继续核验，既不把它写成通过，也不将关闭收益纳入 PF02-A 目标。原始窗口、子进程身份、分段结果及失败假设记录全部保留在证据中；全轮验收仍须 PF07/PF08 收尾。
