## 启动检测的修正

原审计采用简化资源、管道 TTY 与诊断预加载，测量包装后的 init 完成；它没有证明默认资源的启动成本。模型 runtime 的 warm 基准使用 `refreshOnCreate: false`，不能视为完整 CLI runtime 初始化；cold 基准包含工作进程启动，父进程 heap 也不能当作 cold 子进程内存。

新增 `scripts/bench/cli-lifecycle.mjs` 从正式 source launcher 进入，交替执行 minimal/bundled × regular/fullscreen × plain/probe 八个组合，每个组合 2 次预热、30 次独立进程采样。bundled 保留正常资源和工具，使用空工作区与隔离配置；实际加载失败会报错，ACK 同时记录活动工具和命令数量。

这些空子目录位于 checkout 的 `.task-tmp` 下，父仓库发现仍可能参与启动；它们不是任意外部项目或真实用户配置的替代。两组均隔离 HOME/agent/config/session，不读取用户凭据。native smoke 同样使用这些隔离条件。

时间点分开记录：session_start 标题、通过编辑器提交的命令 ACK、probe 的 init 完成、发送 `/quit`、进程 close。ACK 证明输入命令已执行，不等同全部初始化/高亮加载完成；quit 前固定等待 100 ms，该等待不计入 ACK 或 quit-to-close 时间。probe 预先导入 InteractiveMode，会改变导入顺序，因此单独报告，不能从普通结果简单减去探针时间。

每个进程检查一次 ACK、一次 session_shutdown、退出 0、raw mode/括号粘贴恢复，全屏还检查 alternate screen 恢复。使用已有 pipe TTY seam，明确不把此报告标为原生 PTY。保留每个 PID、启动/退出时间和标量结果；所有配置、缓存和原始采样留在当前任务根。

## 比较协议和停止条件

1. 固定源码、锁文件、构建输入/产物摘要、fixture 与 benchmark 源码哈希。先构建再采样；生产无变更也记录实际 dist，不能只依赖包版本。
2. 性能测量串行运行，与构建/测试隔离。后续基线/候选采用交替顺序；每项至少五个独立进程，CLI 每侧至少 30 个有效样本。冷/暖、各配置、原生/管道分别统计，不混成一个均值。
3. p95 使用 nearest-rank；批次均值的 p95 标记其单位。记录原始样本、CV、失败和最大值，不能删慢样本。结构计数及 allocation 另采，禁止把探针回调成本混作生产成本。
4. 常规优化的非目标路径以两组独立重复结果判定：若两组 p95 或采样分配均回退超过 `max(5%, 基线独立进程间 p95 的相对波动带)`，阻止合并并调查；波动带定义为基线五进程 p95 的最大相对中位数偏差，测候选前固定。波动带超过 10% 时先稳定测量，不能把宽波动带当放行条件。
5. 小于计时分辨率/固定开销的变化不作提速结论，依赖确定性访问、扫描和分配计数。缓存/调度优化同时报告即时响应、最终完成时间、总 CPU、保留上限和取消释放，不能只报最早一帧。
6. 正确性、隔离、输出保真和契约的零分配/队列门禁不可用平均时间抵消。对象池仍严格执行契约全部条件，不使用上述噪声协议放宽其硬门槛。

## 待补环境与反例

- PF01/PF03：真实终端的持续输入、缩放、光标/选择和背压；复杂主题/语法高亮、图像回退和超容量输入不能由短静态组件夹具代替。

- PF04/PF06：实际 provider adapter 的字段归一化、请求相关性、schema 原地变化、retry/reconnect 和语义顺序。对在线账户/模型/预算尚无本轮实测；保持独立待验证。
- PF05：完整调用链包含 footer 的版本失效扫描；必须区分同一快照复用、正常追加和分支/恢复重建，不能只优化 `detectCacheMiss()` 后宣布所有历史扫描结束。
- PF07：活动 VM、MCP 和慢输出的实际释放，缺少真实条件时保留具体缺口，不能用空闲退出填充。
