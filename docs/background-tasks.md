# 会话内后台任务

后台任务适合独立的长耗时检查、构建和调查。模型提交前会收到实际并发上限，
上限是容量限制，不能当作创建任务的目标数量。共享文件的编辑、构建和测试应顺序执行。

## 启动和管理

在持续运行的 TUI/RPC 会话中，原有 Bash/PowerShell 参数增加 `background: true`：

```javascript
const result = await tools.bash({ command: "npm test", cwd: ".", background: true, timeout: 600 });
console.log(result.content[0].text);
```

这是 Codemode 调用示例。`cwd` 必须是明确的本机目录；`.` 表示当前工作区。
接受成功会返回任务 ID，只说明任务已接纳；排队和执行都不代表测试通过。
正常的命令检查、权限审批和执行前目录身份检查仍然生效。
后台任务不支持自定义或被替换的执行后端、`commandPrefix` 或自定义 spawn hook。

用户使用 `/tasks` 列出任务，`/tasks status <id>` 查看结果，`/tasks cancel <id>` 取消某项任务。
模型直接使用 `tasks`，不通过 Codemode 调用它：

| 操作 | 参数 | 行为 |
| --- | --- | --- |
| 列表 | `action: "list"` | 分别显示 shell、subagent 的运行、排队和容量 |
| 状态 | `action: "status", id` | 返回状态、已保留的终态文本和结构化 shell 事实 |
| 等待 | `action: "wait", id, timeoutMs: 10000` | 最多等待 60 秒；等待超时不取消任务 |
| 取消 | `action: "cancel", id` | 排队任务不再启动；运行任务先终止进程、清理后再变为终态 |

后台 shell 要求 `tasks` 处于活动工具中；子代理可使用 `tasks` 或兼容的
`subagent_tasks`。通常等完成通知即可，不需要持续轮询。任务完成后，模型应读取
终态结果再判断能否报告成功或重试。退出码、超时、取消和输出记录失败会保留。

## 容量和保留范围

普通命令的配置文件是 `~/.sp/agent/config/background-shell-limits.json`：

```json
{ "maxConcurrent": 16, "maxTasks": 64 }
```

自定义 `SP_CODING_AGENT_DIR` 时使用该 agent 目录下的 `config`。修改后重新加载。

| 限制 | 默认 | 上限 / 行为 |
| --- | --- | --- |
| 同时运行普通命令 | 16 | 64，超过并发数的已接纳任务按 FIFO 排队 |
| 已接纳的运行＋排队普通命令 | 64 | 256；超额时在启动前返回当前占用、请求数量及上限 |
| 单项命令运行时间 | 1800 秒 | 7200 秒；排队时间不计入 |
| 同时等待 | 每类任务 64 项 | 超额明确拒绝；每次等待最多 60 秒 |
| 每类任务终态历史 | 最近 `maxTasks` 项 | 每项最多 12000 个字符（含截断标记）及有限结构化事实；持久会话可跨重启查询 |

两项配置都必须是正整数，`maxConcurrent <= maxTasks`，非法值明确报错。
子代理使用独立的 `subagent-limits.json` 容量，沿用原有工作区冲突检查。
普通 shell 复用授权范围，不提供文件冲突锁；模型负责安排独立工作，避免并发写同一工作区。

普通命令执行时复用有上限的输出缓存和最多 5 MiB 的临时日志。完成后清理日志，
只保留有限的头尾文本；历史被淘汰后，任务 ID 和结果过期。无持久存储的会话在退出后丢失历史。
日志清理失败会保留准确路径与原因，并停止接纳新的后台命令，供用户检查。
需要长期保存的产物应作为正常命令输出文件明确授权，不依赖任务历史。

## 生命周期边界

任务属于当前会话运行时，父模型回合结束或中断不会自动停止已接纳的任务。
明确取消、权限变更、会话替换/树切换、重载或退出会撤销相关运行授权。
后台命令被取消后可能已产生文件变更，检查状态后再决定是否重试。

Print/JSON 等短生命周期模式拒绝后台任务。应用退出后继续执行暂不支持。

手动执行 `quit` 时，如果还有排队、运行或正在取消的 shell/子代理任务，统一显示一次
确认弹窗。重复退出请求共用同一个弹窗；取消退出后，任务继续运行。确认后先取消任务、
等待进程和资源清理完成，再退出。终止信号会跳过或取消弹窗，但仍执行清理。
某个扩展清理失败不会跳过其他扩展；清理失败也不会被报告为成功退出。

## 父子代理预算

`~/.sp/agent/config/task-budgets.json` 控制父会话和子代理的模型请求预算。
缺省或 `0` 表示不限制。空闲时可直接设置，无需重新加载扩展：

```text
/task-budget
/task-budget help
/task-budget set childTurns 20 childTokens 100000
/task-budget set sessionTurns 120 sessionTokens 800000
/task-budget set childTokens 0
/task-budget reset
```

`set` 支持一次设置 1–4 个不同字段，保存到全局配置并立即应用于当前会话；保留已用量，
未指定字段沿用配置文件。其他已经打开的会话需要重载后读取新配置；新会话自动读取。
`reset` 只清零当前会话用量，不修改额度。父模型或子代理运行、排队、清理期间拒绝这两种修改。
字段和值无效、配置损坏或保存失败时明确报错，不切换运行额度。手动编辑 JSON 后仍需重载。
对应配置示例（仅为演示，不是行业推荐额度）：

```json
{ "sessionTurns": 120, "sessionTokens": 800000, "childTurns": 20, "childTokens": 100000 }
```

| 配置 | 范围 | 含义 |
| --- | --- | --- |
| `sessionTurns` | 0–1000000 | 父会话与所有子代理合计的模型请求次数 |
| `sessionTokens` | 0–1000000000 | 父会话与所有子代理报告的 token 合计 |
| `childTurns` | 0–1000000 | 每个新子代理的模型请求次数 |
| `childTokens` | 0–1000000000 | 每个新子代理报告的 token 合计 |

模型在派发前收到上限和会话用量；子代理启动前也会收到预算说明。
父进程同步预留请求次数，因此多个子代理不能同时抢到同一个剩余额度。
额度用完会在下一次请求前拒绝，并说明当前用量和上限，不再启动该请求。
`/task-budget` 查看状态；`/task-budget reset` 仅在父会话和所有子代理停止后重置。
同一会话重载会恢复合计用量；新续跑任务重新计算单个子代理额度，仍累计到父会话。

一回合指一次常规模型请求，不按用户消息数或工具调用数计数。token 按适配器归一化后的
input、output、cacheRead、cacheWrite 相加，每次响应只结算一次；反复发送的历史上下文也会
在每次请求中计入。缓存 token 属于输入用量，但须按适配器拆开的分类计一次，不能重复加。
已发出的请求可以超过 token 上限；这不是硬性账单限额。失败或取消会保留已报告用量，
并标记可能缺失的部分；启用了相应 token 限额时，未知用量会阻止新请求，需检查后手动重置。
费用只是已报告的估计值。当前计数覆盖常规模型轮次，不含独立压缩/分支摘要请求及供应商
内部重试的未报告费用；不要把它当作完整账单。普通 shell 继续使用运行时间和并发限制。

不存在通用的“每个子代理 20 回合／10 万 token”标准。配置表的最大值是输入校验上限，
不是建议额度。可先只限制回合数，观察同类任务的实际用量，再设置 token 限额；例如
每次请求约 5000 输入＋500 输出，20 次约需 110000 token，随着历史增长还会增加。
会话额度应覆盖父代理自身消耗与所有子任务实际消耗的总和，单个子代理额度不会被预先全额扣除。

其他框架采用不同口径：

- [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/subagents) 可设置子代理 `maxTurns`，
  查询级 `maxBudgetUsd` 默认不限并包含子代理费用。
  [查询循环的回合限制](https://code.claude.com/docs/en/agent-sdk/agent-loop) 按工具往返计数，默认不限。
  [统计全树 token](https://code.claude.com/docs/en/agent-sdk/cost-tracking) 需读 `modelUsage`；
  顶层 `usage` 不包含子代理，不能据此判断全部消耗。
- [OpenAI Agents API 用量](https://developers.openai.com/api/docs/guides/agents-api/observability)
  应汇总主代理和子代理各次模型调用。缓存已包含在 `input_tokens`，推理已包含在 `output_tokens`，
  不能把明细再次相加；用量可能暂缺，不代表零消耗。

这些限制不能直接按相同数字互换；先确认统计范围、回合定义以及是否包含缓存和子代理。

## 显式检查点续跑

子代理请求可添加 `checkpoint: true`，显式保存任务提示词及完整回合的文本、工具调用参数
和对应结果。默认不保存这些上下文；不额外保存授权、环境、认证配置或隐藏推理。
文本本身可能包含敏感内容，应按会话数据管理。检查点需要持久会话，普通 shell 不支持续跑。

`tasks status` 或 `subagent_tasks status` 会说明是否有检查点。续跑用新的单项 `subagent`
请求，提供 `agent`、`task`、原来的 `cwd` 和 `resumeTaskId`；`task` 写本次的新指令。
当前角色、信任、模型配置及权限会重新检查，工作区精确身份必须匹配。原任务必须已经结束。
续跑创建新 ID，原结果保留；历史工具调用只作为模型上下文，不自动重放。
续跑的新提示词只在其首个完整回合保存时加入检查点；此前取消或失败不会把未完成指令带入下次续跑。
在检查点之后中断的任务会明确提醒可能存在未记录的副作用，应先检查当前文件。

每个检查点最多 1 MiB、128 条消息，每条最多 128 个内容块；JSON 深度最多 32、节点最多
20000。IPC 单条最多 2 MiB，确认超时 30 秒。图片和不支持的内容会明确拒绝保存，不静默
截断；用量、检查点或通信失败会停止后续模型请求。超出上下文上限时，旧检查点保留，
可以检查工作区后拆分为新任务。真实存储故障则阻止该历史所属任务管理器接纳新工作。

## 重启后的历史

持久会话分别保存 shell、子代理任务的 ID、状态、时间、工作目录、会话分支、有限结果，
以及 shell 的退出和输出事实。恢复同一会话后，`tasks`、`subagent_tasks` 和 `/tasks`
均可查询；结果标记为 `historical`。已完成、失败和取消状态保留；缺少终态记录的任务
变为 `interrupted`，表示完成情况和副作用未知，不代表已证明进程停止。

历史查询不会重新执行任务、重发完成通知、恢复权限或作为当前分支的新验证证据。
对历史记录等待会立即返回，取消也不会操作旧 PID。检查工作区后，需要重新提交并授权才会执行。

首次接纳任务时，按需创建会话文件旁的 `*.tasks-shell-v1.sqlite` 和
`*.tasks-subagent-v1.sqlite`。每类数据库最多保留 `maxTasks` 个未完成记录和
`maxTasks` 个终态记录，硬上限分别为 256；主数据库文件上限为 128 MiB。
普通任务记录只在接纳、启动和结束时写入，不保存完整输出流，也不额外保存命令参数、提示词或凭据。
显式开启的检查点在初始化、模型请求前和完整回合结束时写入同一任务记录，随记录淘汰。
数据库文件名保留 `v1` 以兼容既有路径，内部结构自动迁移到版本 2；旧版程序不支持读取版本 2。
历史数据库独立于会话正文导出：移动或备份会话时需要一起处理；当前会话选择器删除正文时
不会删除这些历史文件，永久清理需同时处理对应文件。

同一会话、同一任务类别只有一个运行实例可以写历史。另一个实例仍存活、无法确认原实例
已退出、文件损坏、版本不支持或写入失败时，会给出具体原因并阻止接纳新任务。
若终态保存失败，本次运行内仍能读取实际结果和保存错误；重启后按最后已保存状态恢复，
不会推断任务成功。未完成记录仅在确认原本机运行实例不存在后转为中断，跨机器的占用记录
不会自动接管。
