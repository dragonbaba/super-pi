# Policy diagnostics and Pi 0.84.1–0.86.1 assessment

This record belongs to the `fix/concise-policy-diagnostics` task branch. It does not change the Super Pi version and does not copy or merge the upstream source tree.

## A: implemented scope

The refusal path now carries a small `PolicyDiagnostic` in machine details and projects a single bounded model view. `packages/extensions/resource-lifecycle-guard/core.ts` records the parsed descriptor-duplication fragment at the redirection scanner, so `2>&1` is reported only when it was recognized as shell syntax. Quoted text and heredoc data remain separate parser cases. The shared `@super-pi/ai` protocol utility now owns feedback sanitization and trusted diagnostic rendering; `packages/agent/src/agent-loop.ts` uses it only on the blocked legacy projection path, while existing machine fields and decision metadata remain readable.

Representative model views are:

```text
[POLICY_BLOCKED:FD_DUP_UNSUPPORTED] Not executed:
Bash analysis does not support `2>&1`.
Next: omit stream merging only if stderr need not pass through the pipe; resubmit for authorization.
```

```text
[SHELL_WRAPPER:LAUNCHER_UNSUPPORTED] Not executed:
Bash analysis cannot inspect the `powershell` launcher.
Next: use an enabled native tool for this query only when it is available; normal authorization still applies.
```

The native-tool sentence is conditional and does not claim that PowerShell is enabled. Permission mode, scope, target identity, cwd, approval state, audit records, `retryable`, and `stateChanged` remain enforcement data. Unsupported syntax remains blocked in `full-access`; the implementation does not add a whitelist, rewrite a command, replay it, or move it to another shell. A user rejection and a protected path use their own conservative categories and do not receive a tool-switch bypass.

The four supplied commands are stored in `tests/policy-diagnostics.test.ts` and are only sent through scanners, preflight, the ExtensionRunner, and an offline Agent fixture. The mixed PowerShell command is refused first by lifecycle preflight because its launcher grammar is unsupported. The `cmd /c` query keeps its existing permission-path order and is refused there for the unsupported descriptor duplication. The other descriptor-duplication cases are refused by the high-risk permission assessment after lifecycle inspection. Backend execution and process creation were both zero.

The fixed token fixture uses `cl100k_base` only as an estimate: the old JSON view measured 65 tokens, the candidate short view 46 tokens, and the provider serializer received exactly the 189-code-unit short text. The candidate is below the 128 estimated-token target. This is fixture evidence, not billing or model recovery-rate data.

The current follow-up assessment is deliberately separate: literal `2>&1` support may be evaluated as a later narrow parser slice, but is not implemented here.

## A–D follow-up repairs on the same branch

The empty `beforeToolCall` reason keeps the old `Tool execution was blocked` fallback for `undefined`, `null`, empty, and whitespace-only values. Structured refusals are projected only when they are trusted pre-execution policy blocks with `stateChanged: false`. The final permission decision (`user_rejected`, `unchanged_rejected_request`, `scope_denied`, protected roots, cancelled confirmation, and expired authority) is selected before primitive hints. A bounded sanitized rejection reason can appear once in the model view and in the compatibility details copy; it never grants permission. A trusted producer diagnostic such as `INSPECTION_LIMIT` is preserved even when the legacy outer `policyReason` is generic, while invalid legacy diagnostic objects fall back conservatively. A later descriptor primitive cannot overwrite an earlier reliable redirection diagnostic.

The provider-wire fixture now uses an assistant tool call, the real ExtensionRunner/preflight hook, an Agent tool result, `convertToLlm`, and the OpenAI-compatible serializer. It records the matching `toolCallId`, one `POLICY_BLOCKED:FD_DUP_UNSUPPORTED` tool result, zero backend executions, two provider requests, no repeated structured JSON, and no `unverifiable_dynamic_scope` primitive in the second request. The diagnostic fixture remains below the 128 estimated-token target (old JSON 65, short view 46 with `cl100k_base`; the actual short wire text is 189 code units). These are offline measurements rather than billing or recovery-rate claims.

`ask_user` retains its existing interaction boundary and now supports a single bounded text question when options would be artificial. Its prompt snippet and one guideline enter the system prompt only while the tool is active. In the controlled UI fixture, four event-loop turns before the answer leave the provider call count at one and the business effect count at zero; a submitted answer produces the second provider call and a persisted tool result. The option path still handles cancellation, duplicate submissions, a queued follow-up, and re-planning. A prose-only question emitted without an `ask_user` call cannot be detected safely without guessing from punctuation, so it remains a model-behavior limitation covered by the active-tool guidance rather than a hidden pause heuristic.

The clean confirmation list now shows bounded date/time, size, and a short session ID. The full exact path remains in the selected-file detail view, with an explicit left/right configured-key toggle and page controls; file/action focus keeps the popup geometry stable. The existing ordinary-child test still covers 100 toggles. A separate production-entry Main and Alt screen-model fixture calls `selectBounded` with its real overlay options, prepaints non-empty ANSI-colored Unicode background rows, opens, navigates, pages, folds, resizes from 50×24 to 30×14, cancels, reopens, and waits for disposal. It checks the nonzero-margin overlay rectangle and background restoration. This is terminal-model evidence; no native desktop window was available in the offline run.

Node recovery has no new length gate and does not require a temporary file. The active Bash metadata gives one short carrier choice: use `node -e` when one-off argv transfer is reliable; use an explicit file or supported stdin when quoting is complex or code is reusable; neither carrier bypasses approval. A short script and a longer valid `node -e` containing Unicode, backslashes, and quotes each execute once in an isolated Bash fixture with no extra temporary-file or syntax-check subprocess. The nested-module syntax fixture preserves the first `SyntaxError` and `invalid.mjs` location; because the outer script already ran, the result is not labeled as an unexecuted policy refusal. The current recovery hint distinguishes recognized parse/module cases; it does not claim a complete outer/argv/nested/runtime classifier, and `ERR_INVALID_ARG_TYPE` is not treated as an argv diagnosis by itself. A checked `.cjs`/`.mjs` file or stdin remains optional guidance for quoting and reuse.

The final Bash error preview now separates failure selection from collapsed layout. The final-result pass selects the first specific exception, a verified Node location/context fragment, terminal status, and whether lower-priority recovery text was omitted; the renderer lays those bounded fragments out within the existing five visual lines. At 80, 100, and 120 columns, the real `ToolExecutionComponent` fixture shows `[eval]:1`, `SyntaxError: Unexpected token '='`, and `Command exited with code 1` even with the complete production recovery hint and a long stack. The recovery text and remaining stack remain in the unchanged expandable content. A repeated render/resizing sequence performed zero additional failure analyses; it performed two width layouts, and the final release reported zero retained preview references. The short `.mjs` source/caret case and ordinary successful tail preview remain covered separately. This records actual collapsed visibility after layout, rather than only proving that the selected summary contained the exception.

The follow-up review also closed three boundary details. Shared feedback sanitization consumes single- or double-quoted multi-word credential values and long paths after key/value separators before the bounded copy is exposed to the model. The selector’s available-row calculation reuses the same two-cell margin and max-height constants as its production overlay, so a 50×24 screen cannot render rows that the overlay later clips. For a final Node parse failure, the collapsed Bash view keeps up to three preceding module/source context lines when they belong to the same location, followed by the first exception and exit status; the full output still owns the remaining stack and recovery text. The next review pass additionally covered quoted absolute paths, authorization-scheme tokens, and an earlier generic Error log before a later structured exception; those cases remain bounded and select the structured exception.
