# 批量目录保留受保护元数据

## 生产原因与范围

目录准备器原先遇到任意嵌套 `.git/.sp` 名称就抛出整调用级 `POLICY_BLOCKED`，普通后代与后续独立项尚未执行。用户明确选择：继续处理普通文件，保留受保护部分并报告。共享 native/worker 树准备器现在只记录被排除名称与已批准普通父目录的索引，不解析、打开、读取或遍历这些元数据，包括 gitdir 文件与目录链接。

copy 排除元数据；move/delete 还保留容纳元数据的祖先目录。完成的普通范围仍是 `succeeded`，`coverageComplete:false` 和有界保留路径说明未覆盖部分。只剩元数据的 delete 是显式 `stateChanged:false` 的成功：结果协议仅在 delete、正整数保留数量和祖先数量、源保留、零文件/目录/字节效果及覆盖不完整同时成立时接受它。宿主回执还必须与准备清单精确一致。日志 commit/result 的改动事实必须一致；其他“成功但无改动”仍拒绝。

普通预检/执行失败继续按项汇总，不重放成功项。直接工作区受保护根、授权撤销、路径重定向、会话/代次变化、取消、传输/日志丢失和未知效果仍遵循原边界；没有给所有 `POLICY_BLOCKED` 降级，也没有新增命令或模型脚本预检。CodeMode 自动展示受保护保留提示，即使脚本未 `show()`；原始会话与先前操作不被重写或重放。

另一个生产问题来自错误包装：一个已成功但截断的 bash 后，另一个子工具失败，父 Script 又附上不相关的“成功输出被截断”提示。新的错误格式化器在确切子调用异常上不附加该提示；旧记录的界面也只识别并消除这段已知重复包装。真正的独立脚本/JSON 解析异常继续显示提示。共用有界诊断处理长错误和 Output 路径，不通过解析任意模型源码判断执行事实。

## 验证与生命周期

真实宿主准备/授权/日志链和受控 worker RPC 覆盖 copy/move/delete、前后独立项、混合普通失败、无改动成功、dryRun、gitdir 文件、受保护 junction、必要祖先保留、有界完整路径与省略计数、伪造路径/数量/覆盖状态/源保留回执。worker 清单另拒绝非法排除名、越界父索引、重复、缺失和计数失配，并验证错误释放后下一次读取。已有权限、替换路径、取消和部分效果回归保留。

CodeMode 真实 VM 验证无显式 show 的保留信息、成功 store 提交、后续脚本、不重放子工具；历史界面折叠/展开只显示一份子错误，原数据 JSON 不变。原有成功命令后的独立 JSON 解析错误用例继续通过。

树清单和排除数组由准备计划持有；执行期祖先 Set 每次操作建立一次，在 finally 清空并释放；清单 reader 的重复索引 Set 在 dispose 释放。路径样本共用现有 800 UTF-8 字节预算，始终保留完整路径，不复制全部排除清单。没有全局缓存或对象池。新增错误格式化只在失败完成阶段执行；普通 delta/progress/frame 通路仅新增一个布尔事实，不增加回调、Promise、AbortController 或逐帧完整输出副本。AST 门禁覆盖共享诊断函数；既有 CodeMode/清理/源不变量覆盖完整生产链。

本机离线探针 `node --expose-gc --experimental-strip-types --test scripts/bench/protected-file-retention.ts` 完成 24 次真实 native 操作、8 份元数据保留、1,280 次折叠/展开绘制（8,320 行）；32 次输出投影，释放后行、结果引用、文本与计时器均为零，受控 GC 后 136 个计划/排除数组/组件/结果 WeakRef 存活为零。一次分配采样估计 39,228,992 字节，10 ms 采样所见最高 heap/RSS 43,480,816/141,967,360 字节，GC 后 heap 24,081,792 字节；约 463 ms，CPU user/system 438/140 ms。主要采样位置包括异步上下文、路径/文件 stat，以及探针自己的渲染结果 join/split。这些是采样和生命周期证据，不是精确分配总量或连续峰值。

既有 `scripts/bench/file-mutations-v3.ts` 的 64 目标/四操作正确工作负载亦完成，449 个计划引用 GC 后存活为零；采样估计 228,462,400 字节，最高 heap/RSS 55,155,624/171,487,232 字节，GC 后 heap 25,128,216 字节。旧实现会拒绝受保护树，不能用遗漏的旧输出与新工作量做提速比较；此处不宣称性能提升。工具说明只在安装时追加固定文字；跨供应商前缀确定性测试覆盖激活、重排、替换和刷新，未改变 provider 请求或历史所有权，不据此宣称在线缓存命中率。

全仓 check/build/test、最终 SHA 的 CI 与评审以关联 PR 为准。这里的 sandbox 证据使用生产 RPC 编解码/清单/宿主验证与本机 worker 执行，替换了 MXC 进程启动，不等同真实 MXC 镜像验证。没有发起付费 provider 请求或重放原会话修改。
