# 项目初始化和索引排除

原 `/project-init` 在写入稳定身份后同步扫描，索引故障覆盖了初始化结果。`/project-status` 也会读取两个完整产物、扫描工作区并重新生成索引。现在初始化和索引分别报告结果。`AGENTS.md` 导航追加一次，状态查询只检查产物元数据和本次会话最近一次构建结果。

根目录 `.spignore` 由现有 `ignore` 库解析。每 1,024 次路径匹配替换一代缓存，复用已解析规则，父路径缓存随同该代释放。匹配目录在展开前裁剪，匹配文件在扫描器读取大小前跳过。npm 验证候选读取实际纳入索引的根清单。Linux 夹具覆盖忽略 `package.json` 而保留 `PACKAGE.JSON` 的情况。

定向回归核实已有规则保持原始 CRLF 字节、重复初始化和刷新保持规则文件修改时间、排除目录和文件各有零次对应扫描调用、状态有零次枚举和产物正文读取。初次索引失败后身份可用于下一次刷新，已有索引时失败保留原有产物。更改位于显式项目命令和扫描路径，不修改帧、事件和工具进度热路径。

Windows、Node 26.13.0 上，在独立 Git 夹具中以相同的 8,001 条索引记录和已发布产物执行前后各 9 次状态查询，交替顺序取中位数。耗时为 108.5 → 49.1 ms，宿主 CPU 为 63 ms → 采样分辨率内的 0 ms。后者不包含 Git 子进程的 CPU。这项对照反映移除主动新鲜度检查后的命令成本。

```powershell
node --experimental-strip-types --test tests/project-context-retirement.test.ts tests/bundled-extensions.test.ts
```
