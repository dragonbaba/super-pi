# Auto 审查看不到被执行的脚本（2026-11-10）

## 问题

`host-auto` 模式下，模型先把 24 KB 的 Blender 脚本写入工作区，再用一行 `exec(compile(open('…/create_lanternbrook.py').read(), …))` 执行。审查模型拿到的只有这一行，以及对话摘录中被截到 800 字符的 `write` 参数。同一个调用第一次被批准，文件修改后第二次被拒绝，理由是“脚本完整内容及保存、覆盖行为不明”。

`/permissions auto` 的选项固定取请求第 3 行作为说明：MCP 工具显示为 `{`，shell 命令显示为 `cwd: …`。

## 修复

不涉及热路径：只在本来要询问用户的调用上执行一次。

- `autoReviewSessionFiles`：请求中出现本会话写入或编辑过的文件路径（绝对路径，或相对工作目录的路径）时，把该文件当前内容放进 `<session-files>` 交给审查模型。最多 2 个文件、共 48,000 字符。
- 只有当文件的 SHA-256 等于会话最后一次成功写入记录的值时才附带内容；被改动、删除或超过 256 KiB 的文件只给出路径和说明。读取量硬限制为 256 KiB + 1 字节，不依赖提前 stat；文件描述符在 finally 中关闭。没有本会话写入记录的文件不会附带；编辑已有文件时，附带的是编辑后整份内容，并非只有模型新增的部分。
- 审查提示词说明该块的来源和用法。
- `/permissions auto` 的选项改为显示 shell 命令本身，或压成一行的参数。

## 验证

对真实会话的副本重放被拒绝的那次请求：`<session-files>` 含完整脚本 23,739 字符，哈希匹配，耗时 1.3 ms。未重新调用审查模型，批准率的变化没有测量。

`tests/auto-review.test.ts` 新增用例覆盖：绝对路径与 `./` 相对路径命中、非会话文件和仅包含文件名的其他名字不命中、文件被改动后不附带内容。`build_scene.py.bak` / `build_scene.py-old` 曾误附带 `build_scene.py`，复现后修正文件名边界；这只影响审查上下文的附件选择，不解析或限制命令执行。

受控复现中，文件在 stat 后从 5 字节增长到 1,048,599 字节，旧实现仍读取并附带内容。改为有界读取后，256 KiB 整可附带（遵守字符预算），多 1 字节即不附带；回归覆盖该边界。

与 `tui-hot-paths`、`bundled-extensions` 回归及类型检查均通过。正则常量放在 `interactive-mode-regex.ts`。本次仅修正说明文本，整体权限 UI 单独处理；没有新增命令解析、预检或限制规则。
