# 首轮顶层工具与权限撤回

会话启动时，工具分类扩展曾移除已经启用的子代理启动器和任务控制工具。精确发现会在对话中途重新加入工具定义。另一个回归发生在用户主动将 `tool_search` 选入 Plan 时，搜索能激活 Plan 范围以外的工具。两种情形均已通过修复前的失败断言复现。

启动时保留当前可用且已启用的顶层控制工具。普通工具继续通过 CodeMode 发现，Plan 自己管理可见集合。项目规则与批准记录由宿主检查，目录撤回后会话使用新的权限范围。

| 离线验证 | 观测 |
|---|---|
| 10 种 API、14 个路由或协议变体 | 每个变体实际序列化 5 个请求。比较首轮、发现后、进入 Plan、继续 Plan、退出 Plan。普通发现保持原有前缀和历史。Anthropic 原生内联协议通过历史中的工具移除与追加表达模式切换。 |
| 首轮后台委派 | 真实会话首轮已声明启动器和控制工具。缺少任务范围的调用被拒绝，完整任务启动后，测试子进程的完成通知唤醒空闲父会话。 |
| 项目规则由询问改为拒绝 | 顶层任务控制、CodeMode 嵌套读取、实际 CLI 子进程委托父宿主的读取均收到拒绝。Responses 测试传输了非空缓存键，审批及撤回前后的固定请求字段相同。 |
| 移除额外工作目录 | 同一文件的写入授权从允许变为拒绝，文件内容完好。目录变更前后的 Responses 固定请求字段和缓存键相同。 |
