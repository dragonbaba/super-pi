# 搜索工具解析与重复探测

当前实现不再为了确认 `rg` / `fd` 可用而执行 `--version`。托管工具目录仍优先；系统工具按 PATH 的文件元数据解析为绝对路径，Unix 同时检查执行权限，Windows 使用原生 `.exe`。`fdfind` 兼容名保留。没有引入全局解析缓存，PATH 变化和文件移除在下一次解析时生效。

Windows 在托管工具之后、PATH 之前保留当前目录的便携程序查找；存在 `NoDefaultCurrentDirectoryInExePath` 时禁止此隐式查找。该边界与 [libuv Windows 查找实现](https://github.com/libuv/libuv/blob/ded7ccfc8a92912983ff7bd38a345c5bd0430291/src/win/process.c) 一致。PR 审查指出遗漏后，先复现了 PATH 程序错误地覆盖当前目录程序，再修复并验证禁用设置、文件移除和下一次解析。

默认模型指引要求直接使用可用搜索工具，复用已核实的环境事实；只有真实可执行文件错误或执行环境变化后才重新排查。自定义完整系统提示仍由调用方负责。

## 验证

- 新增工具解析回归：连续 50 次解析/确保调用产生零个可用性探测子进程；覆盖带空格和 Windows 引号的路径、PATH 切换、文件移除、托管目录优先级、目录误识别、离线缺失和 `fdfind`。
- grep 配置隔离及上下文流测试禁止启动任何同步版本/可用性探测进程，仍实际执行搜索并验证内容、截断与清理。
- 默认提示 golden 更新前，移除新增指引可精确恢复旧 hash；自定义提示和空提示 hash 不变。
- `npm run check`、`npm run build:offline`（12/12 包）通过；审查修正后相关回归 102 成功、3 跳过、0 失败。
- 首次冻结候选的 `npm test -- --keep-going`：463 个测试单元，6330 成功、116 跳过、0 失败或取消。随后 Windows 查找修正重新通过类型检查、12 包构建和受影响回归；跨平台全量 CI 绑定修正后的最终提交。

变更位于工具准备和请求提示构建，不涉及逐行、delta、progress 或渲染热路径；跳过分配基准，不据此声称 CPU 或内存收益。

这里证明本地解析与真实搜索路径，不把测试夹具等同于真实模型会话。模型仍可能自主发起 shell 检查；指引和工具解析共同减少重复探测，不拦截模型脚本。
