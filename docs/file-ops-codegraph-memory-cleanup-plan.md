## 1. A：copy / delete / move

### A1. 目标

1. 新增 `copy`；`delete`、`move` 支持目录和多个目标。
2. 取消条目数上限，包括 `file_batch` 的 16 项。
3. 原生（宿主）与 MXC 沙箱两条链路行为一致。
4. 不改变既有授权决策（审计 D1–D6），不放宽现有的身份、协议和沙箱校验。

### A2. 工具形状

三者都接受单个目标或数组，数组不设 `maxItems`。保留现有的单值 `path` / `destination` 写法。

单值与数组形式互斥：delete 使用 `path` 或非空 `paths`；copy/move 使用完整的 `path` + `destination` 或非空 `items`。同时提供两种形式、空数组或不完整的单值对时按参数错误拒绝。copy 数组的 `overwrite`、delete 数组的 `recursive` 对该次调用的各项一致生效。

| 工具 | 参数 | 语义 |
| --- | --- | --- |
| `copy` | `items: [{ path, destination }]`，`overwrite?`（默认 false），`dryRun?` | 文件或目录。目录递归复制。 |
| `delete` | `paths: string[]`，`recursive?`（默认 false），`dryRun?` | 文件、空目录；`recursive: true` 时删除目录树。 |
| `move` | `items: [{ path, destination }]`，`dryRun?` | 文件或目录，可跨卷。目标已存在即失败。 |

不做通配符展开：模型先用 `find`/`ls` 得到确切清单再传入，授权界面展示的就是将被操作的目标。

`file_batch` 增加 `copy` 操作并去掉 16 项上限；copy 项允许 `destination`、`overwrite`，delete 项允许 `recursive`，默认值与独立工具相同。write 的 `mode` 和正文总预算保留，`dryRun` 仍只在调用层指定；失败处理见 A6。

另增只读查询工具 `file_result({ ref, cursor?, limit? })`，用于分页读取 A8 的结构化记录。`ref` 是会话条目引用，不是文件路径，也不是 Codemode 的临时 `result.ref`；它不读取任意宿主文件、不执行文件变更、不签发读取版本。它的分页限制只约束返回量，不约束原调用执行的目标数量。

### A3. "不覆盖"的保证（修正第一版）

第一版写"同卷用 rename"是错的：预检和执行之间目标可能被创建，rename 会替换它。保证必须来自执行时的原子操作，预检只用于提前报错。

| 操作 | 保证方式 |
| --- | --- |
| 移动独立普通文件，同卷 | 原生环境保留独占 `link` → 复核身份 → `unlink` 源；MXC 在执行前固定选择与跨卷相同的流式复制、重读哈希与身份复核后删源，准备记录标明 `copy_unlink_verified`。真实 MXC 探针确认同一挂载及不同授权挂载均拒绝硬链接（EPERM）；不以失败后的重试或宿主回退实现移动。 |
| 复制文件 | 独占创建目标（目标存在即 `EEXIST`），流式写入。 |
| 复制或移动目录 | 独占 `mkdir` 顶层目标（存在即失败），核对父目录及新目录后才填充。目录 move（含原生同卷）在效果前固定选择独占创建、打开目标身份核验、流式复制和重读哈希，再复核并删除源，不发布源硬链接；准备记录标明 `copy_unlink_verified`。 |
| 移动文件，跨卷 | 按"复制文件"创建目标，校验通过后再 `unlink` 源（见 A4）。 |

目录移动因此不是一次原子改名，而是"建目标 → 逐文件迁移 → 自底向上 `rmdir` 源目录"，中途失败的状态是 `partial`。取得"不替换的原子目录改名"需要平台专用调用（Windows 的不带替换标志的移动、Linux 的 `renameat2`），本计划不依赖它；如后续要做，须先有两个平台的探针证明，再作为单独优化。

目录 move 的验证复制比逐文件硬链接增加 I/O，且不承诺保留目录内或目录外的硬链接拓扑；独立普通文件同卷移动的既有策略保持。路径式 link 的发布瞬间即可暴露源内容，发布后再检查父目录无法撤销这种效果，因此不能用于新建目录中的迁移。

POSIX 填充阶段的目录和文件分别用 0700 / 0600 创建，内容同步、重读哈希和身份核验后才恢复文件 rwx，目录全部填充后自底向上恢复 rwx。验证复制的 move 用已打开句柄恢复准备时的文件修改时间，目录在填充结束后恢复修改时间；沿用 Node 与文件系统的时间精度，不承诺克隆 ACL、属主、ctime 或硬链接拓扑。中途取消留下的未完成候选保持私有。

### A4. 目录与跨卷移动的源删除条件（新增）

移动目录不复用 copy 的"跳过链接"逻辑，否则没迁走的内容会随源一起被删。规则：

1. **预检时源树内有链接、junction 或特殊文件**：整个顶层目标拒绝，磁盘无变化。
2. **逐文件迁移**：每个文件独立完成"创建目标 → 校验 → 删除源文件"。跨卷时校验 = 复制过程中计算的 SHA-256 与目标重读一致，且源文件的身份、大小、修改时间与开始复制时相同；任一不符，该文件不删源，目标保留并标 `requiresVerification`。
3. **源目录只用非递归 `rmdir` 删除**，自底向上。迁移期间新增的文件、未迁走的文件会让 `rmdir` 报非空，这些目录原样保留。不使用递归删除来清理源。
4. **运行中才出现的链接**：不迁移、不删除，所在目录保留。
5. **状态报告**：全部迁走且源目录删净为 `succeeded`；目标已建立但源有残留为 `partial`，结果列出残留的源路径和原因；复制成功但删源失败同样是 `partial`，两边都保留，不自动重试，也不自动删除已建立的目标。

递归 `delete` 用同样的遍历：文件 `unlink`，目录非递归 `rmdir`，遇到链接只删链接本身、不进入其目标。

`copy` 不删除任何东西，所以源树里的链接可以跳过并在结果里计数；复制期间源文件发生变化（大小或修改时间与开始时不同）时，该文件记失败并标 `requiresVerification`。

### A5. overwrite 的含义（修正第一版）

- `overwrite` **只对源是文件的条目生效**：目标是已存在的普通文件时，经现有的"临时文件 → 替换"提交流程替换它。目标是目录、链接或特殊文件时失败。
- **目录不支持覆盖或合并。** 源是目录而目标已存在，一律失败，与 `overwrite` 无关。需要合并时由模型逐文件传入，这样每个被替换的文件都出现在预览和授权里。
- 覆盖工作区外的已有文件仍按 D5 处理（不执行并暂停整轮）。
- 被覆盖文件原有的读取版本作废；预览显示将被替换的目标及其大小。

### A6. 失败后是否继续

| 入口 | 行为 |
| --- | --- |
| `copy` / `delete` / `move` 的数组 | 各顶层目标互相独立。某项 `failed_no_change` 或 `partial` 后继续执行其余项。 |
| `file_batch` | 不变：首个失败即停止，后续项为 `not_started`。 |

以下情况任何入口都立即停止后续操作，未开始的项记 `not_started`：取消、授权被撤销或权限代次变化、会话失效、某项结果为 `state_unknown`。

这需要同步修改执行协议，而不只是改循环：原生侧为新工具提供独立的执行循环（`file-batch.ts:132` 的 `break` 保留给 `file_batch`）；MXC worker 增加"继续执行"的操作类型；宿主回复校验（`workspace-backend.ts:121-135`）对新操作类型不再要求"成功项只在首个失败之前"，改为逐项校验状态与字段的一致性。

#### A7.1. 独立性检查的算法

使用调用拥有的按路径段前缀树检查祖先、后代和完全相同的路径；用 `(device, inode)` 表检查文件身份别名，用规范化键表检查缺失共享父目录的歧义拼写。检查同项的源/目标，也检查不同项之间的所有源/目标，发现冲突则整个调用预检失败。

保留现有比较语义：已存在源之间按平台和真实路径比较；涉及待创建目标时保留 NFC/大小写歧义检查，不把 Linux 上两个不同的既存大小写路径误当成同一路径。前缀树需携带路径角色，区分这些比较，不对全部路径一律转小写。复杂度按全部路径字符数线性计，身份查找不做两两比较；临时树和表在预检失败、取消或调用结束时释放。

不能使用普通字符串排序后的相邻比较：`/repo/a`、`/repo/a-other`、`/repo/a/child` 会漏掉父子冲突。此例、Windows 分隔符、同 inode 的硬链接、大小写/NFC 歧义和缺失共享父目录拼写都进入回归。

### A8. 结果、回执与 MXC 传输（第三版）

#### A8.1. 汇总与会话内记录

第二版的独立 JSONL 结果文件方案退役。复用现有会话 custom entries 承载分段的结构化记录，持久化时写入会话自己的 JSONL，内存会话则只留在其既有内存条目中；不新增会话旁的结果文件、引用数据库或启动扫描。

- 工具结果的有界摘要返回版本、总数、各状态计数、总字节、完成/覆盖标记和失败样本；实际执行产生记录时另给 `resultRef`。`resultRef` 绑定原始调用条目与最新的 v3 记录条目，不是宿主文件路径；没有执行记录的 dryRun 不给该引用。
- copy/delete/move 和新执行的 `file_batch` 都使用 v3，包括只有一项的调用。既有 v1/v2 会话按原格式读取，不改写、不迁移；小结果可保留完整的 `details.items` 便捷视图，大结果明确返回 `itemsOmitted: true` 与 `resultRef`，不把截短的前缀数组冒充完整结果。
- 每个顶层目标有独立终态；目录内部成功文件只记计数。失败/跳过明细按共享预算留样本，并同时记总数、遗漏数、`coverageComplete`；未逐条记录时明确提示重新列目录核验，不能声称掌握所有内部路径。
- 记录不重复完整正文或整份 diff。每段受统一字节预算约束，按记录边界追加，不先物化整批结果或完整行数组。全量目标/终态不会因展示样本耗尽而丢失。
- `dryRun` 只返回有界预览与覆盖说明，不持久化 v3 prepared/intent、创建目录或签发执行许可；实际执行必须重新预检，不能借用预览授权。

#### A8.2. 可信回执与版本延续

v3 继续保留现有的请求—准备—意图—结果配对。新增 `file-mutation-progress-v3` 记录类型，按调用建立顺序链；准备记录全部成功发布并形成 `ready` 记录前，禁止任何用户文件变更。

| 记录 | 必需内容与用途 |
| --- | --- |
| 调用/准备 | 原始调用条目 ID、toolCallId、规范化参数哈希、顶层总数、按全局序号生成的 itemId；每项操作、源/目标真实路径、源与父目录身份、相关 preimage 哈希及操作选项。分段记录全部准备项，`ready` 绑定段数、条目数和清单摘要。 |
| 意图 | itemId、请求与准备摘要、前一条本调用记录 ID、执行时的权限代次；在每个顶层目标产生副作用之前写入。目录中途失败按该顶层目标保守报告，不伪造逐子文件回执。 |
| 结果 | itemId、对应意图引用、状态、`stateChanged`、`requiresVerification`、字节/数量、原因、提交策略及已验证的 preimage/postimage SHA-256。write/edit 保留各自的 commit、snapshot 与 revision 延续事实；copy/move 记录目标验证事实，不能据此伪造原生已读版本。 |
| 结束 | 最新记录引用、链摘要、各状态计数、停止原因及剩余未启动区间。未启动状态须有完整准备记录且没有对应意图；有意图但无可信结果时只能是 `state_unknown`。 |

记录段摘要按原有会话条目和实际序列化字节增量计算，校验记录顺序、调用/条目归属、路径与准备清单、结果字段一致性；日志引用本身不能代替这些校验。`/changes` 与 `file_result` 共用解析器，重复/冲突终态、断链、缺段、摘要不符或不在当前分支的引用都标为不可用/需核验，不自动重放。已被外部整体改写的会话文件不作为防篡改存储承诺，可信程度沿用当前会话历史边界。

实施补充（A 开发中核实）：ready 绑定准备记录的实际条目 ID 与摘要组成的 Merkle root；意图携带该项的成员证明、ready 引用及权限代次。仅比较调用哈希与序号不足以排除指向另一分支准备项的错误引用。活动写入 owner 暂存少于 `2N + proofDepth` 个摘要并在结束/失败/释放时丢弃；读者只缓存一个分支归属证明，反向分页通过至多 32 个子树摘要累计核对完整准备清单，不缓存整批结果或建立整批索引。32 是 JavaScript 数组索引的证明深度，不能作为工具执行条数限制。

MXC write/edit 的每项成功结果保留已验证 SHA-256 snapshot，仍可继续下一次编辑；失败、未知或记录发布失败的项没有后继版本。原生延续仍由原 FileRevisions owner 判断。分页查询仅返回原有证据，不能恢复已失效的 owner、签发新版本或宣称旧 session 中的 revision 仍有效。

任一准备/意图记录写入失败时，该项不得开始；副作用发生后的结果记录失败时停止剩余执行，如实报告已知效果与观察缺口、要求核验且不延续版本，不改报 `failed_no_change`。记录接口必须在原会话写入成功后返回实际条目 ID，不能靠另一次读取 leaf 猜测条目归属。

#### A8.3. 分页读取与生命周期

`file_result` 通过会话已有的条目 ID 索引读取记录，和 `/changes` 使用同一个绑定与分页实现。单页最多 64 KiB 的序列化 JSON（含 envelope），单条记录须能完整容纳；只投影 schema 需要的路径、身份和提交事实，不复制整个 NativePlan、正文或完整预览，父路径可由已记录目标推导时不重复保存。原因和样本按实际 UTF-8 字节裁剪。分页响应保留机器可读的逐项状态、snapshot 和 `nextCursor`，不只给展示文字。页大小不影响执行总量；单条记录/页的最坏编码须由验收证明。

- 查询绑定当前 session owner、权限代次、选中分支、原调用和记录链；cursor 带记录位置和链标识。切换会话/分支、owner 失效或链不匹配时拒绝旧 cursor；仍在派生分支内的 `resultRef` 可重新打开查询。
- 沙箱模式下该工具固定读取应用自己的当前会话结构化条目，不调用 `workspaceInput`、不启动文件 worker、不接受文件路径或任意条目类型、不挂载 agent 目录，也不提供宿主文件工具回退。显式工具许可和会话隔离仍生效。
- 不经普通 `read` 读取会话文件，因此不受 MXC 的 2 MiB 整文件读取条件影响；也不得为查询放宽普通 read 的文件/路径边界。
- 持久化会话随其 JSONL 保存记录；派生会话按现有机制复制选中分支的相关条目，不留下指向原会话磁盘文件的依赖。删除原会话不会破坏派生会话记录；内存会话不生成额外文件，关闭后不承诺跨进程恢复。
- 每页利用已有索引和前一记录引用定位，不调用 `getBranch()` 复制全历史，不为每页建立整批 map 或反复排序。新增缓存如有必要，必须有容量、代次失效和释放证据；活动调用 owner 仅持有必要准备状态，结束/取消/reset/dispose 时释放清单、页缓冲和版本引用。已发布的历史条目由 SessionManager 按原会话生命周期持有，单独计量，不能以此为额外准备清单或缓存免除释放要求。

#### A8.4. MXC 的全调用预检与双向分块

公开调用只有一次，子请求是内部传输细节，不能各自重新审批或重新开始调用。所有源/目标都完成预检与冲突检查，且一次授权绑定完整参数哈希、全局 itemId、准备清单摘要和权限代次后，才能执行第一块。跨已授权工作区的移动/复制分别绑定源与目标的 workspace identity，由宿主分配，不能沿用“目的地默认与源在同一个工作区”的转换，也不接受模型自行提供 workspace index。

1. **prepare**：在现有串行 operation owner 内，对所有分块运行只读预检。目录身份清单过大时流式写到既有 MXC 控制/交换目录中的本次临时 artifact，返回固定身份与摘要；宿主只能按预先分配的 artifact ID 读取，拒绝 worker 提供的任意路径、链接、身份或摘要变化。它不进入模型上下文，也不是第二份持久化结果记录。
2. **全局 ready**：收齐每项准备结果、完成跨块冲突检查和一次授权后，重新验证所有准备清单。将 v3 准备记录与 ready 发布到原会话；任一失败均不执行任何目标。`dryRun` 在此执行阶段之前返回并释放临时准备状态。
3. **execute**：每块携带原调用标识、全局序号区间、清单摘要和当前权限代次；执行每项前重复身份、受保护路径与授权检查，不能把 prepare 得到的身份替换为执行时重新接受的基线。宿主按原请求验证回复的序号、操作、状态、snapshot 与停止原因，去重且不补发可能已经执行的块。
4. **停止与释放**：`file_batch` 的普通失败阻止发送后续块；数组工具仅对可继续的独立项继续。取消、权限失效、会话失效、`state_unknown`、记录/传输失效均停止后续块，保留可能已发生效果的意图。临时准备 artifact 在成功、拒绝、失败、取消和 sandbox dispose 时按本次记录的身份清理，不扫描或删除其他调用文件。

每个子请求同时满足 **请求 JSON 不超过 4 MiB、回复 JSON 不超过 256 KiB**。分块根据完整 envelope、全局序号、路径、正文、JSON 转义及错误样本的字节预算确定；一次调用的 write/edit 正文 1 MiB 预算在分块前统一累计，不按块重置。复用实际发送的已序列化字符串计数，不为计量再 stringify/编码一份。单项不能通过该传输时在全调用预检阶段报出原因，不允许先执行前面的块再发现无法提交后面的项。

#### A8.5. 实施顺序

在 A 的同一个 PR 内，先完成 v3 schema/记录 owner/分页读取与旧回执分流，再接入全调用准备和双向分块，最后开放新操作及去掉公开条目数上限。接口只在完整路径与生命周期回归通过后切换，不发布“执行已放开、回执尚未能追溯”的中间状态。

### A9. 仍然保留的限制

- 变更文本 1 MiB：只约束 `write`/`edit` 携带的正文，copy/delete/move 不带正文。
- 预览有界：`dryRun` 返回总数、总字节、有界路径样本与覆盖说明；询问界面按页显示每个顶层目标的条目数、字节数和路径。工作区外目标必须全部可浏览，确认一次绑定全清单，不能把被裁掉的样本当成授权范围。
- 其他现有校验不变：受保护路径按真实路径判定；目录树内含 `.git`/`.sp` 保护根时整个顶层目标拒绝；源与目标互相包含的条目在预检阶段拒绝；预检全部完成后才开始执行；工作区外条目在一次询问里全部列出。

### A10. 验收

1. 原生与 MXC 各测：复制文件、复制目录树、目标已存在（默认失败 / 文件 `overwrite` 成功 / 目录即使 `overwrite` 也失败）、递归删除、同卷移动目录、跨卷移动文件与目录。
2. **竞争**：预检通过后由另一进程创建目标，再执行复制和移动（文件、目录各一例），目标内容不被替换，源保留。
3. **跨卷移动的源保护**：源树含链接（预检拒绝，无变化）；迁移期间向源目录新增文件、修改未迁移文件（结果 `partial`，新增与被改文件留在源，目标不含错误内容）；删源被占用（`partial`，两边都在）。
4. **失败后继续**：数组中间一项失败，其余项完成；`file_batch` 仍在首个失败处停止。取消、授权撤销各一例，后续项为 `not_started`。
5. **规模**：copy/delete/move 数组与 `file_batch` 各覆盖 2,000 个顶层目标，另测一个含 5 万文件的目录。执行完成；工具结果字节有界；MXC 请求/回复分别不超过 4 MiB / 256 KiB，给出实际最大值。用长路径、非 ASCII、转义字符、失败样本和 write/edit 混合输入验证，不只测短路径成功项。
6. 目录树内含 `.git`：整项拒绝，磁盘无变化。递归删除遇到链接：只删链接，目标内容仍在。
7. 工作区内外混合删除：一次询问列出全部工作区外条目，拒绝则整批不执行。
8. **跨块预检与停止**：最后一块含重叠、受保护路径、无效参数或无法传输的项时，前面各块也无变化；授权拒绝同样无变化。ready 后改变某项源身份，执行时该项不得使用新身份继续；取消/撤权、传输截断或结果未知后不再发块、不重放。
9. **v3 与旧会话**：`/changes` 和 `file_result` 可分页访问第 17、513、2,000 项，状态与磁盘一致；未启动恢复和剩余草案不截到前 16 项。v1/v2 历史夹具照常解析，仍拒绝缺失/冲突的旧证据；恢复正文预算保持，超预算草案明确提示分页/分阶段处理，不扩大执行数量限制。
10. **版本延续**：原生与 MXC 的小结果及 `itemsOmitted` 大结果各测 file_batch write/edit → 查询对应项 → 继续 edit；无需补读的场景继续成立。外部修改、失败/未知项、owner 失效或 session 重载不凭分页结果恢复已失效版本。
11. **记录与读取**：注入准备、意图、结果记录写失败，分别证明不开始、停止后续、如实报告已有效果。断链、缺段、伪造目标、重复终态、错调用/错分支引用、无效 cursor 都不能成为可靠回执或绕过核验；确认不会自动重放工具。
12. **生命周期**：持久化记录总量超过 2 MiB 时，MXC 下仍能通过 file_result 分页读完，每页不超过 64 KiB；普通 read 对工作区外路径和超过容量文件的拒绝不变。派生会话后删除原会话，派生记录仍可查询；切换/重载、内存模式、子代理隔离与取消不遗留额外结果文件、临时准备 artifact 或 owner 引用。
13. **独立性**：覆盖 A7.1 的父子路径被无关路径隔开、跨块重叠、硬链接身份和歧义拼写；以等价的递增规模工作负载给出路径节点/比较次数、内存与耗时，证明不再做平方级两两比较。
14. **热路径**：结果汇总、记录追加、分页和 `/changes` 的查找属于大结果处理/证据查找，按[热路径契约](performance/hot-path-allocation-contract.md)审计完整生产调用链，包括既有会话追加路径。循环内不建逐项闭包、Promise 尾链或整份结果副本；给出确定性计数、峰值/保留内存、CPU 与取消/flush/dispose 后引用释放证据。文件变更本身不在热路径清单内。

## 3. C：记忆批量清理

### C1. 目标

像清理会话那样，在一个列表里勾选多条记忆后一次删除。只由用户显式触发，不做任何自动过期。

### C2. 入口

`/memory` 菜单新增一项"批量清理记忆"，不新增斜杠命令。技能已有多选删除（`/memory` → 管理技能），本项不涉及技能。

### C3. 流程

1. **选范围**：用户偏好 / 全局记忆 / 当前项目记忆 / 全局纠错 / 当前项目纠错 / 所有项目。
2. **选筛选**：全部 / 超过 30、90、180 天未修改 / 自定义天数。纠错范围另有"已过注入窗口的临时失败"（默认 7 天，`[correction]` 条目除外）。
3. **多选列表**：按最久未修改排在前。每行显示来源、类别、创建日期、最后修改日期、字符数、首行摘要。筛选只是预先勾选，可以增减。
4. **确认**：显示条数、涉及的文件和将释放的字符数。
5. **执行、同步索引、报告**：见 C4–C6。

无交互界面时不删除任何内容。

### C4. 保留原始字节的删除路径（修正第一版）

现有读写流程会 `trim()`、去重并重新拼接，不能复用来做批量删除，否则未删除条目的字节会变，同文条目也可能被一并去掉。新增专用路径：

- **列表来自原始片段。** 读取文件原始字节，按分隔符切开但不裁剪、不去重。每条的身份是（文件真实路径，片段序号，片段原始字节的 SHA-256）；元数据不同但正文相同的两条、不同作用域的两条，都是不同的条目。同时记录整个文件的指纹。
- **执行在现有的 Markdown 写入锁内。** 重新读取原始字节：整文件指纹与列表时不同，则该文件整体跳过并报告，不尝试按内容重新匹配。
- **删除区间按连续选中组计算。** 对不在文件开头的选中组，移除该组及其前面一个分隔符；从文件开头开始的选中组，移除该组及其后面一个分隔符。组内分隔符一并移除，区间不重叠；其余原始字节（包括未选片段的首尾空白）不重新编码。全部删完时写成空文件，不删除文件本身。覆盖首项、末项、相邻组、隔项和全选，不能因两条选中项共用分隔符而留下空条目或误删未选字节。
- **发布沿用现有机制**：抽取可接收原始 bytes 的安全发布 helper，保留同目录临时文件、发布前/后指纹与身份核验、独占发布及冲突恢复，不简化为无条件 rename 覆盖。发布期间发生外部冲突时跳过并报告该文件，不把旧选择重新匹配到新内容后重试。
- 完成后让内存中的 store 从磁盘重新加载。之后通过 `memory` 工具做的普通增改仍走原有流程（会规整空白和去重），那是既有行为，不在本项范围。

### C5. "所有项目"的范围（补充）

复用索引同步已有的目录规则：只处理名称带哈希身份的项目目录；链接目录、链接文件一律不读不改；已退役的旧式目录不列出、不删除，界面只提示"另有 N 个旧目录未列出"。包含所有符合当前身份规则的目录，即使对应项目根已不存在也照常列出；`project.ts` 的目录名使用根路径哈希，不能从名称可靠还原项目根，因此本轮不提供“孤儿项目”自动判断或筛选。

### C6. 搜索索引同步（补充）

Markdown 是正本，索引是派生数据，两者不是同一个事务：

- 全局和当前项目：删除后通过已绑定的观察器对账。
- 其他项目：这些 store 是为本次清理临时创建的，没有观察器。删除后对受影响的项目逐个调用索引同步流程里已有的"按项目对账"逻辑，只处理本次改过的项目。
- **索引同步失败或 SQLite 不可用**：Markdown 的删除不回滚。报告写明"已从 Markdown 删除 N 条，搜索索引未同步：<原因>"，并提示运行 `/memory` → 同步搜索索引 恢复。此时 `memory_search` 可能暂时还能搜到已删条目，报告里要明说。

### C7. "过期"的定义

- 条目只有创建日期和最后修改日期，没有"最后被用到"的记录。筛选条件是**多久没被修改**，界面文字按这个写。
- 不新增使用追踪：那需要在每轮或每次检索时写文件，违反该包的约束。
- 没有元数据的旧条目标"日期未知"，不参与天数筛选，但可手动勾选。
- 删除是直接删除，与会话清理一致；不新建回收目录或第二份索引。

### C8. 界面实现与热路径（修正第一版）

多选界面的按键处理和渲染属于"交互更新、渲染/布局"热路径，不能以"启动摘要和每轮钩子不变"为由跳过。

- 仓库里已有两套多选：memory 包内的技能管理界面（已懒加载）和 `session-memory-manager` 的 `BoundedMemorySelector`。实施时先比较两者，选用**不需要改动既有渲染与输入循环**的那一套；优先同包内复用，避免跨包移动。
- 如果只是给现有组件传入新的行数据：声明"组件未改动"，验证新增代码不在每次按键或每帧里重建行数组、排序或过滤（行数据在打开时构建一次，勾选状态增量更新）。
- 如果需要修改或移动组件：按热路径契约审计完整调用链，运行相关 AST/源码不变量和分配基准，给出确定性计数与释放证据。
- 界面代码保持懒加载，不进入启动路径。memory 从 `dist/index.js` 加载，包内相对导入继续使用 `.js`，包含懒加载的动态 import；本项不改其编译配置。直接从 TypeScript 源码加载的 `session-memory-manager` 或 `tui-kit` 才使用真实 `.ts` 扩展名；如果复用跨包组件，须先证明 memory 的 `rootDir`、构建与产物解析兼容，不能直接把源码相对路径接进编译产物。

### C9. 验收

1. 全局、当前项目、跨项目各删多条：被选条目消失；**未删除条目的原始字节逐字节不变**（含首尾空白的夹具）；索引同步成功后 `memory_search` 搜不到已删条目。
2. 两条正文相同、元数据不同的条目只勾一条：只删被勾的那条。
3. 勾选后、确认前外部改写其中一个文件：该文件跳过并报告，其他文件正常删除。
4. 注入索引同步失败：Markdown 已删，报告含警告与恢复方法；随后手动同步，搜索结果恢复一致。
5. "所有项目"遇到链接目录、链接文件、旧式目录：不读取、不修改，旧目录计数正确。
6. 天数筛选的边界日、无元数据条目、`[correction]` 条目各有用例。
7. 无界面模式不删除；取消或 Esc 后磁盘无变化，不留锁、临时文件或 WAL/SHM。
8. 在 `packages/memory` 运行其 `AGENTS.md` 清单中的 `npm run check`、`npm test`、`npm run benchmark:lifecycle`、`npm run smoke:rpc`，按 C8 给出界面验证；从实际构建的 `dist` 打开批量清理菜单，确认动态 import 可解析且界面仍懒加载。涉及源码扩展时再运行根目录的 bundled extension 导入回归；不把其他包的 `.ts` 规则套进 memory 编译产物。
