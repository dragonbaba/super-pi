## 证据与根因

## 修复

后端在请求中单独传入会话工作区，不修改命令文本。来宾将已捕获的只读快照或可写副本关联到相同拼写的项目路径；非 C 盘通过已有的来宾盘符机制访问该路径。PowerShell 及其原生子进程以这个项目路径作为 cwd，文件工具仍使用同一工作区相对路径或绝对项目路径。

只读模式的目标仍是只读映射；读写模式的目标仍是 VM 内的副本，结果继续经过已有的候选验证和宿主写回授权。没有挂载宿主项目或整块磁盘。路径与来宾运行时、已有目录冲突，或者父目录/联接发生重定向时明确失败，不覆盖冲突目录。命令仍限定 PowerShell 7，超时、Job 所有权、输出边界及权限规则不变。

更新工具描述、README、执行环境说明和真实 VM 回归断言，退役对外要求使用固定 `C:\SuperPiInput` / `C:\SuperPiWorkspace` cwd 的说明。

## 性能与资源

审计链路为工作区工具 → 后端串行请求 → 来宾 catalog/命令目录准备 → C# CommandInfo/Job/Pump → 变更候选 → 原有写回/关闭所有者。新增目录准备位于显式命令边界，不在输出块、进度或渲染循环执行。每个 VM 创建一个工作区联接，后续命令核对身份；目录分量数组受输入路径长度限制。

新 helper 的闭包、正则、new 表达式、await 均为 0，没有对象池。既有 11 个 worker 函数内容不变；C# Job/Pump 及旧任务实现的完整前缀内容不变。原生精确分配/受控 GC 契约通过：输入 131073 字节，保留 32768 字节，34 次读取，分配与清除均 36864 字节，liveBuffers=0，9 项非法包拒绝。此计数验证未改动的输出所有者，不宣称新目录检查没有文件系统开销或启动加速。
