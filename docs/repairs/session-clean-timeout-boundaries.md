## A: `/memory-sessions clean`

The confirmed cause was one selector index spanning read-only file rows and actions. The initial index therefore pointed at a non-selectable file row, while Enter was presented as a general action. Detail lines were conditional, so changing focus changed the component height.

The selector now keeps independent bounded browse and action indices. The dangerous permanent-delete action cannot be the default; the default action is cancel. File rows are labelled read-only, Tab switches browse/actions, and confirmation is accepted only in the action focus. Configured keybindings provide the confirmation/cancel hints. Key release, key repeat, and bracketed paste are ignored. The detail area has a fixed bounded allocation, is recalculated with available overlay space on resize, clears stale lines, and keeps long paths inspectable. Narrow/short windows show an enlarge/cancel message and disable dangerous confirmation. The selector reuses TUI `truncateToWidth`, `wrapTextWithAnsi`, and shared key parsing.

Synthetic tests use fictional paths only. The Main and Alt TUI frame paths are exercised with 100 focus/navigation toggles; the terminal viewport and frame writes do not accumulate the full path. Existing candidate identity, lease, current-session, managed-directory, and replacement checks remain in the deletion routine. Cancelling stage two preserves the recovery file while reporting earlier index cleanup separately.

## B: Bash GNU `timeout`

GNU Coreutils documents `timeout option... duration command arg...`. This repair recognizes only the bounded subset `timeout <positive integer seconds> <literal command> <args...>`. It does not execute, probe, or rewrite the wrapped command.

Zero/dynamic durations, dynamic programs, missing operands, unknown timeout options, excessive duration, unsupported `--`, excessive nesting, and Windows `timeout.exe` are conservatively refused with a specific wrapper reason. After recognition, the real command continues through lifecycle, mutation, path, permission, dynamic execution, and final authorization checks. The supplied Bash commands are parsed as separate 250-second and 200-second subcommands; no `/d` scan ran. `2>/dev/null` is harmless diagnostic redirection; other output redirection remains mutation evidence. `find -delete`, `find -exec`, deletion commands, scripts, dynamic programs, pipelines, and nested wrappers retain conservative checks.

## Hot-path and lifecycle review

The post-publication review followed the production chains rather than inspecting only the changed functions:

- A: `memory-sessions` registration → selector construction and parent overlay space → Main/Alt input dispatch → bounded title/file/action/detail layout → frame generation and terminal write → close, cancel, and `dispose`. Construction prepares sanitized labels, descriptions, details, and display strings once per selector. Input is per explicit event; `render` is per frame and only recomputes detail wrapping when the focused item or width changes. The active frame owns its returned line array; `dispose` clears callbacks, layout lines, item records, and browse/action indices.
- B: Bash preflight → tokenization and shell segment boundaries → the shared `timeout` wrapper parser → lifecycle checks → mutation primitives and targets → path/permission scope → final authorization. A recognized timeout only advances a bounded token index. It never authorizes the inner command, probes a program, rewrites the command, or skips the existing checks. Ordinary commands retain the existing scan path.
- C: credential resolution/storage/env/explicit headers → retired subscription rejection or normal API credential selection → Anthropic client headers and message conversion → request/stream/retry → completion and cancellation. The retired OAuth route rejects before transport, refresh, or retry. Normal API authentication is prepared once per request; provider delta handling does not rescan credentials, headers, tool tables, or history.

The targeted evidence is deliberately split by lifecycle. The selector regression exercises method output and actual Main/Alt frame writes, repeats focus/navigation 100 times, checks stable height and bounded path occurrences, and disposes both overlays and terminals. ## Follow-up candidate: redirection context and detail-cache evidence

This follow-up uses the published candidate `6e08fd47440796b528941ce0dba21213796db582` as its immutable comparison point. The production paths audited were `inspectBashResourceLifecycle` → `inspectLifecycleScript`, `inspectHighRiskBashMutation` → `inspectShellScript` → `parseShellSegments`, and `inspectBashPermissionScope` → `inspectScript` → `inspectTokenBuffer`; the selector path was `memory-sessions` → `selectBounded` → `BoundedMemorySelector` → Main/Alt component rendering and frame writing.

Before this follow-up, the lifecycle entry returned `undefined` for `printf '%s\\n' $((8 >> 1))` and returned the existing `[SHELL_HEREDOC]` refusal for `cat <<'EOF'\nliteral > victim.txt\nEOF`. The mutation entry nevertheless reported an `output_redirection` target ending in `\\1` for the arithmetic case and a target ending in `\\victim.txt` for the quoted heredoc case. The permission entry reported the same false targets. This was a lexical-context error, not Bash execution: the operator scanners saw `>>` inside arithmetic and `>` inside heredoc data.

The fix adds one shared, lazy shell analysis view. It tracks arithmetic depth before output-redirection recognition and masks heredoc operator, delimiter, and body text while preserving source newlines and later commands. Ordinary commands without arithmetic or heredoc markers take the existing direct source path. It supports multiple heredocs on one header line, reports an opaque bounded `heredoc_uninspectable` primitive, and recursively sends substitutions from an unquoted heredoc body through the existing nested scanner. A quoted body therefore contributes no fake file target; `echo x > after.txt` after the delimiter still contributes `after.txt`; `$(echo nested > nested.txt)` in an unquoted body still contributes `nested.txt`. The lifecycle entry remains conservatively refused for heredocs, and `2>&1` remains unverifiable. Timeout-wrapped commands use the same mutation and permission analysis after wrapper recognition.

The selector now separates the currently displayed detail from its one-instance cache. A no-detail action paints the bounded blank detail rows but does not discard the most recently wrapped file detail. The cache is replaced when the file, sanitized detail text, width, or explicit invalidation changes; `dispose` clears its text, lines, items, and callbacks. Returned line arrays are still call-owned. The production wrapping counter in the selector and the regression test show one initial wrap per instance for the same file, zero additional wraps over 100 file/action toggles, and one new wrap after resize; two instances keep distinct arrays. The action frame contains no previous file path.
