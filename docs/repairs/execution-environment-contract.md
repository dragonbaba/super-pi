## 方案与执行顺序

1. 统一执行能力契约：会话模式、可用命令、路径范围和网络配置由同一运行环境产生；会话恢复采用宿主本地绑定记录，模式切换完成后才保存。
2. 命令环境：Bash 与 PowerShell 共用沙箱、工作目录、进程族监督和结果协议；从宿主进程与持久 PATH 发现工具，保留明确的进程优先级并过滤不适用条目。
3. 输入命名空间：项目与明确授权的外部输入使用一致的绝对路径；命令和文件工具遵守同一边界，目录不存在与未授权可区分。
4. 产物发布：文本编辑保留文本协议；通用命令使用字节产物协议，容量按元数据和文件流分别控制，不把所有内容装入 JSON/base64，不套用 32 个文本编辑的限制。保留完整预检、原文件身份/hash 和每项发布凭证。
5. 失败模型：区分命令启动、执行、结果收集和宿主发布；保留有界 stdout/stderr、退出码、超时、确切容量和已发布数量；禁止自动重跑有副作用命令。
6. 更新过时文档，构建本地离线版本；统一契约的单元/真实 Windows Sandbox 验收完成后才判定修复。

## 验收矩阵

- 新会话默认沙箱；同机同会话恢复三种模式；分叉/导入/另一工作区不继承授权；切换失败和取消不保存新授权。
- Bash/PowerShell 7 使用相同项目路径，中文/空格/单引号目录可用；无 5.1 回退；命令失败/超时进程族结束。
- 新增机器 PATH 工具在环境刷新时发现；原进程明确 PATH 顺序保持；不继承凭据或整个宿主用户目录。
- 所有已添加工作区可读；沙箱读写分别校验与写回，只读模式各根均拒绝写入；未添加目录、越界、链接和目标替换被拒绝。
- 超过 32 张 PNG、超过文本单文件限额的二进制产物按字节一致发布；已有二进制覆盖、删除及宿主并发修改受版本约束。
- 容量失败包含实际值与限额；命令成功但发布失败不得伪装成 shell 启动失败；部分发布有精确回执。
- 相关源代码不变量、分配计数、受控 GC 和关闭引用释放证据。

## 已落实的统一契约

- 本地会话执行记录绑定会话文件、ID、主目录、机器和用户；新建/导入/分叉不继承。权限和目录替换成功后才保存；失败停止执行，不保存尚未应用的目录授权。旧日志不能单独授予宿主权限，升级前会话需手动选择一次。
- `/add-dir`、`/remove-dir`、`/dirs` 原生管理最多 16 个不重叠工作区，文件工具、命令工具和发布采用同一个目录列表。移除已消失目录仍可恢复使用。读写副本隔离、宿主版本检查和只读模式约束适用于所有根。
- Bash 与 PowerShell 7 共用 Windows Job 监督、工作目录和结果协议；直接 `!` 入口也走工作区适配器，拒绝自定义宿主 operations，保持终端控制字符清理。不会根据命令字符串猜测或改写路径。
- 新 VM 通过固定 PowerShell 7 查询刷新机器/用户 PATH，与进程 PATH 去重合并，保留进程优先级；统一 Windows `Path/PATH` 拼写。实机发现 ImageMagick，无逐工具配置或 5.1 回退。
- 源快照按 256 KiB scratch 流式复制和哈希，合计 16 GiB/20,000 条目、单源文件 8 GiB。命令仅比较文件版本，变化文件才读取内容；未变化的 2 MiB 夹具实测内容打开次数为 0。
- 通用命令使用字节产物通道，最多 1,024 项、64 MiB/文件、256 MiB/调用；JSON 不装载字节或 base64。文件移动和批量操作复用该通道，跨根 move 明确拒绝。文本编辑的原限额保持独立。
- 宿主在第一次发布前验证所有候选的路径、重复项、容量与 hash，再通过原生 FileService 逐项提交。源基线来自宿主捕获/发布记录；覆盖、删除、目录变化、并发修改和权限代次检查保留。
- 错误区分 execution/collection/publication，保留实际退出码和有界输出。发布失败报告确认提交数量、可能部分变更数量及原生凭证；命令已执行时禁止自动重放。

## 性能、所有权与验收

完整审计链：原生权限与执行边界 → WorkspaceSandboxTools → WorkspaceSandboxBackend 的捕获/串行调用 → guest catalog/commandChanges → C# Job/Pump 与 CapturedProcess → 候选预检 → FileService/commitPreparedFile → 发布凭证与 VM/文件清理。PATH 发现、会话保存和目录切换仅在明确生命周期边界执行；输出块、权限反复核验、provider/渲染路径不新增命令扫描、Promise 或控制器。

分配探针调用生产候选读取函数，48 × 2 MiB：预检累计 48 × 256 KiB，发布累计 48 × 2 MiB；一次只持有一个发布载荷，96 个 buffer WeakRef 在 4 轮受控 GC 后存活 0，owner 清空。此探针不把累计分配当作峰值，也不宣称磁盘复制零成本。

生产输出/授权探针处理 17,825,792 字节、272 块，只保留 32,768 字节；2 个流缓冲，共 32,768 字节；逐块闭包、数组、包装、Promise、控制器均为 0。各 200,000 次授权检查，9 个生命周期目标在 4 轮 GC 后存活 0；唯一子进程关闭。未引入对象池。

当前本地检查：类型检查、源码/热路径不变量、相关回归、原生文件服务、会话目录替换及真实 VM 均通过。源版本和离线产物分别验收；产物覆盖 50 个文件、2 MiB 二进制覆盖/移动/删除、附加目录和混合根 batch、宿主并发修改保留、中文/空格/单引号 cwd、两根只读、失败退出 23、实际进入 Bash 后超时及关闭。具体计数、构建摘要和复现命令见[结构化证据](../evidence/execution-environment-contract-2026-11-05.json)。

## 交付约束

PR #228 首轮审查发现两个遗漏：附加工作区独有盘符没有传给命令监督器，以及直接 `!` 的适配器错误可能显示正常完成。修订后，worker 显式传递所有工作区盘符，C# 在启动前映射；真实 VM 以 C 盘 cwd 和一个没有工具链的附加来宾盘符验证两种 shell。适配器错误进入直接命令拒绝路径，TUI 用独立失败标志显示 `(failed)`，不编造进程退出码。51 项定向回归、109 项热路径检查和修订后的离线产物实机测试通过；直接 Bash 生产组件 100 次失败完成/渲染/释放后，4 轮 GC 存活 0，采样计入冷完成分配，不宣称逐帧性能提升。首轮 head 六个 CI 分片全通过，但修订 head 仍须重新审查与全量 CI。

应用核心需重新启动才能载入新构建；升级前的旧会话需手动选择一次建立本地记录。原生交互 `!` 沙箱输出在命令完成后有界交付，尚不提供 VM 内后台任务；网络继续使用显式配置。大输入首次快照仍有 I/O 成本，不承诺所有带注册表/驱动依赖的宿主工具可直接在 VM 工作。

提交采用独立 PR。首次推送等待 reviewer；同 PR 后续推送必须 `@codex review`。仅最终 head 审查无未处理意见且全部 CI 通过后合并，再回 main 并按精确分支名清理。更早 PR #227 的审查与 CI 不作为本次证明。临时资源仅清理本任务登记的根和已确认结束的所有者；最终清理结果随交付回执报告。
