# 会话权限与沙箱

直接运行 `superpi`，进入会话后输入 `/permissions`（也支持 `/permission`）选择权限。普通启动只有这一条入口；不需要通过启动参数切换沙箱。

| 选项 | 工具执行位置 | 项目文件行为 |
| --- | --- | --- |
| 只读（沙箱） | Windows Sandbox | 从只读挂载的项目快照读取；文件工具拒绝变更，命令写入该挂载也由系统拒绝。 |
| 沙箱读写（默认） | Windows Sandbox | 在沙箱内部副本上读写；成功结果经过宿主版本、路径和授权检查后写回工作区。 |
| 全部读写（宿主机） | 当前宿主系统 | 明确确认后使用宿主工具，可访问工作区外路径；仍保留显式拒绝、文件版本检查及元数据保护。 |

前两个选项都在沙箱内执行。只有第三项退出沙箱隔离。选择模式时保留当前会话 ID 和对话历史，先撤销旧授权、停止并等待旧任务与沙箱关闭，再接入新运行环境。切换失败时停止执行，不悄悄沿用旧权限或回落宿主。

状态栏显示当前权限。重新选择同一沙箱模式会重建工作区快照；`/reload` 也会关闭旧 owner 并创建新的延迟启动沙箱。新建、恢复或分叉会话都不继承宿主读写授权，需再次显式选择。首次实际调用文件或命令工具时才启动 VM，同一权限代次后续调用复用它。

## 沙箱的工作范围

当前支持本机已验收的 Windows Sandbox CLI 0.8.107.0 及固定 Windows 编译工具链。缺失、不符或无法确认清理时明确失败。SDK 和非交互兼容入口仍可使用旧 `executionEnvironment`；该旧配置及 `--execution-environment` 不覆盖交互界面的三档权限选择。

沙箱输入是当前工作区快照，排除 `.git`、`.sp`、`.artifacts`、`.codegraph` 和 `node_modules`。工作区快照不接受符号链接或重解析跳转。私有输入、运行器和从宿主 PATH 发现的工具安装目录均只读映射给来宾，单独映射私有结果交换目录；项目原目录不作为工具目录映射。沙箱读写模式在来宾私有目录创建可写副本，宿主写回由原生文件服务完成。

| 边界 | 当前上限/行为 |
| --- | --- |
| 工作区快照 | 20,000 个条目、总计 256 MiB、单个源文件 64 MiB |
| 文本读取 | 单文件 2 MiB；单次至多 2,000 行和 32,768 字符，附当前内容 SHA-256 snapshot |
| 搜索 | `ls` / `find` / `grep`；字面子串匹配，至多 200 条；grep 跳过大于 2 MiB 的文件 |
| 写回 | 每次至多 32 个文件、单文件 1 MiB（与原生写入共用上限）、合计 16 MiB；UTF-8 文本；批量入口至多 16 项 |
| 命令 | 只使用 PowerShell 7；来宾验证 Core / 主版本 7，禁止兼容模式隐式启动 5.1；默认 30 秒、最多 120 秒，同一会话串行执行 |
| 工具链 | 默认从宿主 PATH 自动发现完整安装目录，去重并生成来宾 PATH；当前应用的 Node 安装优先，npm/npx 随其安装目录可用 |
| 外部通道 | VM 网络、剪贴板、音视频、打印和 vGPU 关闭；模型 provider 在宿主侧通信 |

宿主需要完整的 PowerShell 7 安装。优先使用全局 `powershellPath`，否则从 PATH 和标准安装位置发现 `pwsh.exe`；缺失时明确失败，不回退 Windows PowerShell 5.1。UTF-8 脚本无需为 5.1 添加 BOM，错误按纯文本返回。命令及其后代由同一个 Windows Job 管理；成功、失败或超时都必须确认进程族结束。沙箱中未接入的 Bash、MCP、浏览器、LSP、自定义宿主工具与后台任务不会绕过边界在宿主执行。需要网络或当前快照预算之外的大型构建时，可由用户明确选择第三档。

### 自动发现工具目录

正常使用无需逐个配置工具。发现逻辑保留 PATH 优先级，识别 `bin`、`cmd`、`Scripts` 的安装布局，并带入同一安装目录内的 DLL、标准库和辅助程序。WinGet Links 解析到实际安装目录，Rustup 的工具链目录单独只读映射，不映射 `.cargo` 根目录。Java、Go、.NET、Android 等需要的安装根环境变量转换为来宾路径；不会整份继承宿主环境变量、用户配置或凭据。

用户目录下的 SDK 同样可以按安装布局发现，但不会把整个用户目录或 `.cargo` 凭据目录作为安装根。没有显式安装根环境变量时，Go、Java 和 .NET 使用 PATH 中第一套通过安全检查的安装；宿主显式设置的安装根仍优先。工作目录先解析真实路径，再检查工具挂载与项目的重叠，使用目录联接进入项目也不能绕过隔离。

C 盘安装保留安装路径；其他盘的安装挂载到 `C:\SuperPiToolchains\<盘符>\...`，并在来宾创建仅指向这些已映射目录的盘符别名，兼容工具内的绝对安装路径。这不会映射整个宿主磁盘。来宾使用自己的 home、TEMP、npm/Cargo/.NET 缓存。工具安装保持只读；安装新组件、联网下载或依赖宿主注册表、服务、驱动的程序，不因出现在 PATH 就保证可用。项目 `node_modules` 仍不随工作区快照进入沙箱。

发现发生在每个新 VM 启动时。无效、失效、系统 PowerShell 和 OS 应用别名路径被过滤；工具树中指向安装目录外的链接、无法读取的目录和超出检查容量的自动发现项被跳过。必需的 PowerShell/Node 或显式补充目录不满足条件时停止启动。检查按目录异步进行，最多 128 个挂载、每棵树 250,000 个条目、总计 2,000,000 个条目；不复制整套 SDK，也不在每次输出时扫描。工作区模式可用 `Get-Command <工具>` 检查实际入口，`C:\SuperPiTools\toolchains.json` 查看跳过目录及原因。修改 PATH 或安装工具后，通过 `/reload` 或重新选择沙箱模式建立新 VM。

只有例外才需要全局 `~/.sp/agent/config/settings.json` 的 `sandboxToolchains`：`include` 为 PATH 外的安装/可执行目录数组，`exclude` 为不应映射的目录数组。两者均要求本地绝对路径；排除子目录也会排除包含它的整个安装挂载。项目设置不能扩大这些宿主读取范围。无需为已经正常出现在 PATH 的 Python、Git、Go、Java 等逐项填写配置。

快照不会自动跟随外部编辑器修改。写回前对比原宿主目录身份、原文件身份/版本和内容 hash；冲突时停止写回。命令失败、超时、取消或旧代次结果不写回。失败后清理旧 VM 和快照；确认清理完成后，同一会话的下一次调用会捕获新快照，不重放失败命令，也不自动切换宿主执行。清理无法确认时保留原 owner 并拒绝继续。

整组候选的路径、重复项、编码、1 MiB 单文件及 16 MiB 总容量在第一次写入前检查。来宾写入、编辑结果和命令候选也使用宿主传入的同一单文件预算。多文件提交仍按项进行，已经完成的项不自动回滚；后续实际提交冲突会报告已确认发布的文件数，不能把批量操作视为事务。文本读取/编辑拒绝无效 UTF-8，搜索跳过非 UTF-8 文件。

```javascript
const source = await tools.read({ path: "build.ps1" });
const result = await tools.powershell({ command: "& ./build.ps1", timeout: 30 });
await show(result.ref);
```

新工作区模式不需要手工声明 `inputs` / `writes`；读取和变更都发生在同一沙箱工作区。直接覆盖或编辑已有文件仍需真实 `read` 返回的 snapshot，不能自造或从旧快照复用。旧有界任务协议保留给非交互/SDK 兼容消费者，不能套用到上面的新工具参数。

## 默认值与额外规则

全局 `~/.sp/agent/config/settings.json` 可保存 `permissionMode: "read-only"` 或 `"sandbox-write"`。未设置时默认沙箱读写；项目配置不能扩大权限。`host-write`、历史 `full-access` / `never-ask` 以及旧会话授权均不会恢复为宿主模式。菜单只改变当前会话，不写入全局默认值或删除历史记录。

三档模式内已支持的操作默认按当前模式允许。原 `executionPermissions.rules` 中的精确 `deny` / `ask` 继续生效，拒绝优先于询问、询问优先于允许。规则可限定工具名、精确命令和工作区相对子树；不猜测 shell 风险等级。`approval: "never"` 仅表示没有交互批准渠道，需要询问的调用返回 `APPROVAL_REQUIRED`。Plan 模式另行拒绝命令与变更。

一次授权绑定原工具、原参数、当前会话和权限代次；切换后不能复用。用户拒绝保留在当前会话历史，写回时使用稳定的候选内容和版本作为拒绝身份，不因重新生成原生 revision ID 而再次获准。

搜索路径默认是工作区根目录。子目录的 `deny` / `ask` 同样约束覆盖该目录的搜索；限定子目录的 `allow` 不扩大为整个工作区授权。路径规则和目标均解析实际目录身份，目录别名不能绕过规则。宿主模式的 `lsp_fix(write: true)` 属于变更，授权绑定 `root` 与 `path` 对应的文件，并受 Plan、受保护路径和权限撤销约束；预览不取得写入授权。

宿主读取和搜索使用工具自身的路径规范化规则，授权后执行绑定已核准的实际路径，`@`、`~` 或文件名兼容拼写不能指向另一授权对象。原生写入/编辑按各自的路径规则检查，包括批次内每一项。沙箱搜索支持 `src`、`./src` 和 `src/example.txt`，目录范围不误匹配 `src-other`。

宿主模式为子代理、结构化只读命令及浏览器执行签发当前调用的凭证；子代理逐项绑定工作区身份和读写能力，结构化命令绑定 cwd、参数及精确外部根。路径规则先于凭证签发生效，权限切换撤销未完成调用。Plan 中子代理降为只读，浏览器代码执行被拒绝。这些扩展没有沙箱后端，在前两档仍明确返回不支持。

宿主模式仍属于受信任执行。扩展初始化、provider 与应用自己的会话持久化运行在宿主；沙箱隔离的是已接入的文件/命令工具执行，不把整个插件进程宣称为 VM 内运行。

## “离线”与启动的关系

`superpi` 是日常启动命令。已有构建可直接运行，不需要另选“离线版”或“沙箱版”。`npm run build:offline` 只是维护者的构建命令，使用本地模型目录数据；`superpi --offline` 仅跳过启动时的更新、目录刷新等网络操作。它们都不选择权限模式，也不会把远程模型变成本地模型。

实现、实机验收与性能证据见[总进度记录](Super%20Pi%20权限简化与原生能力整合方案.md)和[性能检查](performance/native-sandbox-closeout-2026-11-03.md)。旧失败、停止与旧任务协议的记录保留为历史证据；当前交互行为以本页为准。
