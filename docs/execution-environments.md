# 会话权限与沙箱

直接运行 `superpi`，进入会话后输入 `/permissions`（也支持 `/permission`）选择权限。普通启动只有这一条入口；不需要通过启动参数切换沙箱。

| 选项 | 工具执行位置 | 项目文件行为 |
| --- | --- | --- |
| 只读（沙箱） | Windows Sandbox | 从只读挂载的项目快照读取；文件工具拒绝变更，命令写入该挂载也由系统拒绝。 |
| 沙箱读写（默认） | Windows Sandbox | 在沙箱内部副本上读写；成功结果经过宿主版本、路径和授权检查后写回工作区。 |
| 宿主机受限 | 当前宿主系统 | 明确确认后使用宿主工具。工作区（含 `/add-dir`）内的文件工具操作、只读命令，以及目标全部在工作区内的已识别文件命令直接执行；其余命令、MCP 调用和工作区外的读写先询问。敏感目标与外部覆盖照常拒绝。 |
| 宿主机受限 · Auto 审查 | 当前宿主系统 | 与宿主机受限相同；本来要询问用户的操作先由当前会话模型审查，批准即执行，拒绝则不执行并把原因告诉模型。见下文“Auto 审查”。 |
| 宿主机完全权限 | 当前宿主系统 | 明确确认后使用宿主工具，可访问工作区外路径；仍保留显式拒绝、文件版本检查及元数据保护。旧记录中的 `host-write` 即此档。 |

前两个选项都在沙箱内执行，后两项退出沙箱隔离。选择模式时保留当前会话 ID 和对话历史，先撤销旧授权、停止并等待旧任务与沙箱关闭，再接入新运行环境。切换失败时停止执行，不悄悄沿用旧权限或回落宿主。

状态栏显示当前权限。重新选择同一沙箱模式或执行 `/reload` 会关闭旧 owner 并创建新的延迟启动沙箱。同机恢复同一会话会保留用户手动选择的模式和附加目录；新建会话仍默认沙箱，分叉、导入、复制或改变主工作目录不会继承授权。本机记录绑定会话文件、ID、主目录、机器和用户，存放于 `~/.sp/agent/session-execution/`，不从历史消息恢复权限。升级前的旧会话需手动选择一次以建立记录。首次实际文件/命令调用才启动 VM，同一权限代次复用它。

`/add-dir <directory>` 添加工作区，`/remove-dir <directory>` 移除，`/dirs` 列出。路径可包含空格，整条剩余参数作为一个目录；也接受外层引号。至多添加 16 个不重叠的目录。相对路径以主目录为基准，绝对路径可访问任一已添加目录。添加和移除通过同一执行边界关闭旧任务、更新所有工具并重建快照，不从命令文本猜测目录，也不挂载整个磁盘。只读模式所有目录均只读；沙箱读写模式分别校验并写回对应宿主目录。

## 沙箱的工作范围

当前支持本机已验收的 Windows Sandbox CLI 0.8.107.0 及固定 Windows 编译工具链。缺失、不符或无法确认清理时明确失败。SDK 和非交互兼容入口仍可使用旧 `executionEnvironment`；该旧配置及 `--execution-environment` 不覆盖交互界面的四档权限选择。

沙箱输入是当前工作区快照，固定排除 `.git`、`.sp`、`.artifacts`、`.codegraph` 和 `node_modules`，默认还排除目录 `target`、`.venv`、`__pycache__`（下述全局配置可调整）。工作区快照不接受符号链接或重解析跳转。私有输入、运行器和从宿主 PATH 发现的工具安装目录均只读映射给来宾，单独映射私有结果交换目录；项目原目录不作为工具目录映射。沙箱读写模式在来宾私有目录创建可写副本，宿主写回由原生文件服务完成。

| 边界 | 当前上限/行为 |
| --- | --- |
| 工作区快照 | 所有目录合计 20,000 个条目、16 GiB；单个源文件 8 GiB；按最多 256 KiB 缓冲复制与哈希，大目录首次捕获仍有磁盘 I/O 成本 |
| 文本读取 | 单文件 2 MiB；单次至多 2,000 行和 32,768 字符，附当前内容 SHA-256 snapshot |
| 图片读取 | `read` 按内容识别 JPEG、PNG、GIF、WebP、BMP；单图至多 16 MiB，通过独立字节附件返回，并复用普通读取的图片缩放；offset/limit 只作用于文本 |
| 搜索 | `ls` / `find` / `grep`；字面子串匹配，至多 200 条；grep 跳过大于 2 MiB 的文件 |
| 文本编辑 | 写入/编辑单文件 1 MiB；文本候选合计 16 MiB；批量入口至多 16 项，仍要求当前 snapshot |
| 命令产物 | 每次至多 1,024 个变更、单文件 64 MiB、合计 256 MiB；支持二进制。JSON 只传元数据，字节单独传输，宿主逐文件验证与发布 |
| 文件移动/批量 | 复用字节产物通道，支持二进制；单次至多 32 个变更；批量可包含不同已添加工作区的操作，跨工作区 move 不提供隐式复制删除 |
| 命令 | Bash 和 PowerShell 7 共用 VM、路径和 Windows Job；验证 PowerShell Core / 主版本 7，禁止隐式 5.1；默认 30 秒、最多 120 秒，串行执行 |
| 工具链 | 默认从宿主 PATH 自动发现完整安装目录，去重并生成来宾 PATH；当前应用的 Node 安装优先，npm/npx 随其安装目录可用 |
| 外部通道 | VM 网络默认关闭，由全局 `sandboxNetwork` 显式控制；剪贴板、音视频、打印和 vGPU 关闭；模型 provider 在宿主侧通信 |

宿主需要完整 PowerShell 7 安装；优先使用 `powershellPath`，否则从 PATH/标准位置发现，缺失时明确失败。Bash 从已映射的安装目录发现，禁止回退宿主或 WSL；Bash 本体缺失会给出明确诊断。两种 shell 的脚本保持原文，共用进程族回收；直接 `!` 命令也使用当前沙箱 Bash。MCP、浏览器、LSP、自定义宿主工具和后台任务尚未接入沙箱，不会绕过边界执行。

读取图片时，在 CodeMode 使用 `const r = await tools.read({path: "preview.png"}); await show(r.ref);`。图片字节不经过 stdout 或 JSON/base64 文本窗口；shell 输出有上限，不能用 `base64` 命令代替图片读取。不支持的二进制格式需先转换为 PNG 等支持格式；超过 16 MiB 的图片需先缩小。宿主仅处理校验过的来宾附件，不通过重新打开宿主原路径绕过快照；附件处理完成后释放。内联图片沿用普通 `read` 的 2000×2000 和约 4.5 MiB base64 处理上限，非视觉模型仍不能理解图像。图片输入上限约束编码文件大小，不代表解码器峰值内存上限。

### 工作区路径与网络配置

文件工具（包括批量操作）接受主工作区相对路径，也接受任一已添加工作区内的宿主绝对路径。例如从 `D:\Projects\Example` 启动后，`ls({ path: "D:/Projects/Example" })` 与 `ls({ path: "." })` 指向同一快照。处理另一个目录使用 `/add-dir`；未添加路径、UNC、设备路径不会自动扩大范围。

PowerShell 的当前目录与会话项目路径一致。例如从 `D:\Projects\Example` 启动后，命令中的 `$PWD`、`./src` 和 `D:\Projects\Example\src` 都指向同一份沙箱工作区，文件工具使用相同的相对或绝对项目路径。来宾仅为已捕获的快照或可写副本建立这个路径，不直接挂载宿主项目或整块磁盘，也不改写命令文本。只读模式仍由只读映射阻止写入；路径与已有来宾目录冲突或被重定向时明确失败。工具描述提供工作区和网络状态。若宿主项目本来为空，沙箱副本也为空。

在全局 `~/.sp/agent/config/settings.json` 中合并以下字段即可允许工作区沙箱联网：

```json
{ "sandboxNetwork": "enabled" }
```

`"disabled"` 或未设置表示禁网；其他值明确报错。修改后重新启动会话或执行 `/reload`，新 VM 才使用新配置。项目配置不能启用网络。该开关适用于前两档工作区沙箱；旧 SDK 显式 `inputs` / `writes` 协议仍保持离线。

禁网时，交互会话里的常见联网命令（npm/pnpm/yarn install、pip install、git clone/fetch/pull/push、curl、wget、Invoke-WebRequest 等）执行前会询问“允许本会话的沙箱联网？”。同意后关闭当前 VM，之后的命令在联网的新 VM 中运行，直到会话结束，状态栏显示“沙箱已联网（本会话）”；拒绝则命令不执行。这项同意不写入任何配置。没有交互界面时（子代理、print 模式）不询问，命令照常离线运行。没有识别出的联网命令在禁网下失败时，结果会说明是禁网导致。

命令里的盘符绝对路径如果只存在于宿主机（不在任何工作区、工具链挂载或 VM 自带目录内），命令不会执行，当前整轮任务暂停并给出该路径；需要访问时由用户用 `/add-dir` 添加目录。沙箱不会自动扩大工作区，也不提供沙箱外重跑。

启用后通过 Windows Sandbox 虚拟网络访问外网及可达的局域网，并非域名白名单。DNS、代理、系统策略和防火墙仍可能影响连接；不继承宿主代理凭据，也不自动更改防火墙。网络由 Windows Sandbox 的 [Networking 配置](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file)控制，与构建用的 `build:offline` 和启动用的 `--offline` 无关。

读写模式可在 VM 中运行 `npm install`。`node_modules` 不参与文件工具搜索和宿主写回，关闭或重建 VM 后需要重新安装；清单、锁文件、图片和构建产物按各自协议发布。只读模式不能向项目快照安装依赖，可使用来宾临时目录。

### 仅在 VM 内保留的目录

全局 `~/.sp/agent/config/settings.json` 的 `sandboxPrivateDirectories` 控制初始导入和宿主写回共同排除的目录，默认如下：

```json
{ "sandboxPrivateDirectories": ["target", ".venv", "__pycache__"] }
```

单个名字匹配每层同名目录；包含 `/` 的条目（如 `build/private`）只匹配每个工作区根目录下的该相对目录。匹配不区分大小写，接受 `\` 分隔符；不支持绝对路径、`..` 或通配符，最多 64 条。配置数组替换默认列表，`[]` 可关闭这三项可选排除；固定的元数据和依赖排除仍保留。普通文件恰好名为 `target` 不受目录规则影响。配置在创建沙箱 owner 时固定，修改后执行 `/reload` 或重启；项目配置和工具参数不能覆盖它。

这些目录在初次捕获时就跳过，不计入快照容量，宿主已有内容不会导入或被删除；来宾新建的内容也不写回。沙箱读写模式可通过命令和原生文件工具读写、搜索其中的产物，关闭或重建 VM 时丢弃。需要交付到宿主的文件请放在未排除的目录，或先调整配置。规则仅跳过实际目录；符号链接沿用原有拒绝规则，不会跟随链接读取其他目录。

### 自动发现工具目录

正常使用无需逐个配置工具。发现逻辑保留 PATH 优先级，识别 `bin`、`cmd`、`Scripts` 的安装布局，并带入同一安装目录内的 DLL、标准库和辅助程序。WinGet Links 解析到实际安装目录，Rustup 的工具链目录单独只读映射，不映射 `.cargo` 根目录。Java、Go、.NET、Android 等需要的安装根环境变量转换为来宾路径；不会整份继承宿主环境变量、用户配置或凭据。

用户目录下的 SDK 同样可以按安装布局发现，但不会把整个用户目录或 Cargo 凭据目录作为安装根。默认 `.cargo` 和宿主自定义 `CARGO_HOME` 都按真实路径保护，只允许映射其中的 `bin` 可执行子目录。显式 PATH 目录保持原顺序，自动补充的 `bin`、`Scripts` 排在其后；没有显式安装根环境变量时，Go、Java 和 .NET 按实际可执行目录的顺序选择第一套通过检查的安装。宿主显式设置的安装根仍优先。失效的 WinGet 别名只跳过自身，不中断其他工具发现。工作目录先解析真实路径，再检查工具挂载与项目的重叠，使用目录联接进入项目也不能绕过隔离。

C 盘安装保留安装路径；其他盘的安装挂载到 `C:\SuperPiToolchains\<盘符>\...`，并在来宾创建仅指向这些已映射目录的盘符别名，兼容工具内的绝对安装路径。这不会映射整个宿主磁盘。来宾使用自己的 home、TEMP、npm/Cargo/.NET 缓存。工具安装保持只读；安装新组件、联网下载或依赖宿主注册表、服务、驱动的程序，不因出现在 PATH 就保证可用。项目 `node_modules` 仍不随工作区快照进入沙箱。

每个新 VM 启动时，通过 PowerShell 7 读取机器/用户的持久 PATH，与进程 PATH 去重合并；进程明确设置的顺序优先，Windows 的 `Path/PATH` 大小写统一处理。安装程序更新持久 PATH 后，`/reload` 即可发现新增工具。只查询 PATH，不整份读取或继承宿主环境。无效目录、系统 PowerShell、OS 应用别名和越界链接被过滤；必要工具或显式补充目录不满足条件则失败。最多 128 个挂载，每棵树 250,000 项、总计 2,000,000 项；只在 VM 启动检查，不按输出扫描。`C:\SuperPiTools\toolchains.json` 列出跳过原因。

只有例外才需要全局 `~/.sp/agent/config/settings.json` 的 `sandboxToolchains`：`include` 为 PATH 外的安装/可执行目录数组，`exclude` 为不应映射的目录数组。两者均要求本地绝对路径；排除配置同时保护填写路径和解析后的真实路径，子目录尚不存在时解析其已有父目录。排除子目录也会排除包含它的整个安装挂载，不退回单独映射 `bin`。无法读取排除目录的身份时停止启动。项目设置不能扩大这些宿主读取范围。无需为已经正常出现在 PATH 的 Python、Git、Go、Java 等逐项填写配置。

快照不会自动跟随外部编辑器修改。写回前对比原宿主目录身份、原文件身份/版本和内容 hash；冲突时停止写回。命令失败、超时、取消或旧代次结果不写回。执行前参数错误、普通读取业务错误或修改前的过期 snapshot 拒绝，只有在能确认没有副作用时才保留当前 VM，便于重新读取后继续。已经开始修改、创建附件、运行命令，或身份、完整性、清理无法确认的失败仍清理旧 VM 和快照；确认清理完成后，下一次调用捕获新快照，不重放失败命令，也不自动切换宿主执行。清理无法确认时保留原 owner 并拒绝继续。不会从命令文本推断“只读”或决定复用 VM。

整组候选在第一次发布前检查路径、重复项、容量与字节哈希。命令仅比较执行前后的文件版本，对变化文件计算内容哈希；宿主基线由捕获/发布时记录维护，不接受来宾指定的宿主基线。文本编辑验证 UTF-8；二进制发布复用原生创建/提交的路径身份、权限和版本检查。每次只保留一个产物缓冲，预检使用至多 256 KiB；多文件按项提交，失败报告已发布数量，不自动回滚或重跑。

结果区分 launch、execution、collection 和 publication。即使命令退出 0，收集或发布失败仍为失败，并保留有界 stdout/stderr、退出码、超时/截断事实和容量诊断。宿主变化、取消、进程族未关闭或授权过期均不继续发布。

```javascript
const source = await tools.read({ path: "build.ps1" });
const result = await tools.powershell({ command: "& ./build.ps1", timeout: 30 });
await show(result.ref);
```

新工作区模式不需要手工声明 `inputs` / `writes`；读取和变更都发生在同一沙箱工作区。直接覆盖或编辑已有文件仍需真实 `read` 返回的 snapshot，不能自造或从旧快照复用。旧有界任务协议保留给非交互/SDK 兼容消费者，不能套用到上面的新工具参数。

## 默认值与额外规则

全局 `permissionMode` 只决定新会话的 `read-only` / `sandbox-write` 默认值。明确手动选择由本机会话记录保存，不修改全局默认值。历史 `full-access` / `never-ask`、项目配置和导入的消息不能授予宿主权限。

旧交互命令 `add_workspace`、`remove_workspace` 和 `/permissions status|scope|approval|...` 已由原生入口接管并提供退役提示。旧 `executionEnvironment` 和显式 `inputs/writes` 协议仍有 SDK/非交互消费者及回归测试，暂保留兼容入口；它们不决定当前交互模式，不提供宿主回退，也不在普通工具说明中宣传。

只读、沙箱读写和宿主机完全权限三档内已支持的操作默认按当前模式允许；宿主机受限按上表默认询问的部分不在此列，匹配的 `allow` 规则可免去这些询问，但不越过敏感目标与外部覆盖拒绝。原 `executionPermissions.rules` 中的精确 `deny` / `ask` 继续生效，拒绝优先于询问、询问优先于允许。规则可限定工具名、精确命令和路径；相对规则路径仍以主工作区为基准，附加目录可用绝对规则路径限定，不改变已有规则含义。不猜测 shell 风险等级。`approval: "never"` 仅表示没有交互批准渠道，需要询问的调用返回 `APPROVAL_REQUIRED`。Plan 模式另行拒绝命令与变更。

宿主机两档中，`rsync --delete` 和 `find … -delete` 删除的是目标目录里的文件，不删目录本身：目标在工作区内的普通目录时，与其他工作区内删除一样不额外询问；目标是工作区根目录、包含或位于 `.git`/`.sp`，或在工作区外时询问一次（工作区根目录下的同步可能删掉 `.git`，所以仍然确认）。

MCP 工具在宿主机完全权限默认允许，在宿主机受限默认询问；远端工具声明 `annotations.destructiveHint: true` 时，即使同时声明了其他较低权限的提示，也会在执行前询问一次（与 Codex 的破坏性注解审批一致）。`readOnlyHint` 不授予任何额外权限。规则的 `tool` 除精确名称和 `*` 外，还可以写 `mcp__<server>`，或以 `*` 结尾的服务器模式，如 `mcp__github__*`、`mcp__github__get_*`（与 Claude Code 的 MCP 规则写法一致）。`<server>` 可写配置中的服务器 ID（如 `GitHub`），也可写工具名里规范化后的写法（如 `github`）；模式其余部分按规范化后的工具名匹配。服务器 ID 可含 `__`，因此按注册该工具的服务器身份判断，不从工具名推断。`allow` 模式必须指明一个服务器，`ask`/`deny` 可用 `mcp__*` 覆盖全部 MCP 工具。指明该工具或其服务器的 `allow` 规则视为用户的长期批准，可免去破坏性注解的询问；全局 `*` 不算。沙箱两档仍不提供 MCP（MCP server 运行在宿主机上，不受 VM 边界约束）。

### 项目共享规则与“不再询问”

每个项目文件夹有一份规则文件：`~/.sp/agent/projects/<项目路径哈希>/permissions.json`，同一文件夹的所有会话共用。文件放在用户目录下，克隆来的仓库不能自带授权。`/permissions rules` 显示文件位置和当前规则；可以直接编辑，保存后下一次授权生效。删除文件即清空规则。

```json
{ "version": 1, "rules": [
  { "tool": "bash", "decision": "allow", "command": "npm test *" },
  { "tool": "bash", "decision": "deny", "command": "git push *" },
  { "tool": "mcp__docs__search", "decision": "allow" }
] }
```

- `command` 只用于 `bash` 和 `powershell`，按词匹配：单独的 `*` 匹配任意多个词（`npm test *` 也匹配 `npm test`），词内的 `*` 匹配任意字符（`npm run test*`）。PowerShell 规则不区分大小写（逐个字符折叠，非 ASCII 字母也一样）。不写 `command` 时匹配整个工具，与命令能否解析无关；其他工具只能按精确名称写，`file_batch` 中的每项操作也按各自的工具名匹配。`read` 的 `deny`/`ask` 也约束 `/changes` 的“核对当前状态”（它没有对话框，两者都会阻止）。
- 复合命令逐段匹配，`deny`/`ask` 会跳过段首的控制结构关键字（如 `then git push`），PowerShell 脚本块里的命令（`try { git push } catch { … }`，大括号紧贴单词也算）逐条匹配，Bash 的 `command`、`sudo`、`env`、`timeout`、`time`、`xargs` 等分派前缀之后的命令、PowerShell 赋值右侧的命令（`$null = git push`）也参与匹配，`git.exe`、`npm.cmd` 和 `/usr/bin/git` 按去掉目录和启动器后缀的名称匹配，`find -exec`/`-execdir` 执行的命令和 `bash -c '…'`、`pwsh -Command …`、`cmd /c …` 的脚本和 PowerShell `@(…)` 的内容（按调用工具的规则）也参与匹配，Bash `case` 的分支模式（`git)`）、PowerShell 哈希表的键（`@{ npm = "10" }`，带引号的键 `'k'=git push` 的值照常匹配）、`switch` 的分支标签和放在命令位置的字符串（`$label = 'npm'`、here-string `@'…'@`，`& 'npm'` 才是调用）不算命令；程序自己的全局选项不归一化（`git -C repo push` 不匹配 `git push *`，可写 `git * push *`），heredoc 正文按数据跳过，正文之后的命令照常匹配；无法确定 heredoc 结束位置时询问。任一段命中 `deny` 即拒绝，命中 `ask` 即询问；拒绝优先于询问，询问优先于允许。`deny`/`ask` 在所有档位生效，与 `executionPermissions.rules` 一起排序。
- `allow` 只免去宿主机受限的“其他命令”和 MCP 工具询问。要被允许，一段命令须为顶层的字面量简单命令（不含变量、命令替换或后台运行）。允许的命令之后再出现文件命令或文件重定向仍会询问，因为前面的命令可能已经改了文件。含 heredoc 的 Bash 命令不受 `allow` 影响，也不提供“不再询问”。工作区外路径、无法确认的变更目标、写入已有目录、敏感目标拒绝和外部覆盖拒绝都不受 `allow` 影响。
- 文件解析失败时继续使用上一版规则并提示一次，不会放宽；此时“不再询问”也不写入。保存时先按读取时的限制校验整个文件，多个会话用锁文件依次保存，手动编辑若恰好发生在读取与替换之间，会重新合并。

宿主机受限档的审批对话框在可以靠规则免去询问时，多一个“允许，并在本项目不再询问”，并列出将保存的规则：每个需要审批的程序存一条前缀规则（`npm test --grep x` 存为 `npm test *`，`ls -la` 存为 `ls *`，单独的 `make` 原样保存），一条命令最多 5 条；MCP 工具保存该工具名。工作区外路径、显式 `ask` 规则等靠保存规则也免不了的询问，不提供这一项。

**Auto 审查**（`/permissions` 第 4 档）：什么操作需要审批与宿主机受限完全一致，只是由当前会话模型代替用户回答（参照 Codex 的 auto_review）。

- 审查模型看到精简的对话记录和完整请求（参照 Claude Code 的 auto mode）：用户消息，以及助手调用的工具名和参数（参数截断到 800 字符）。助手自己的文字、推理内容、工具输出和扩展记录都不给审查模型，避免助手或外部内容替自己说情。最多 16 条、约 12000 字符；请求即审批对话框里的同一份详情。
- 回答须以 `APPROVE:` 或 `DENY:` 开头。`DENY` 时操作不执行，模型收到 `[AUTO_REVIEW_DENIED]` 及原因。审查没有得出结论（无法解析、请求失败或 60 秒超时）时不算拒绝，也不计入熔断：改为照常询问用户；没有界面时返回 `[APPROVAL_REQUIRED]`，并说明这不代表操作不安全（参照 Codex 把超时与拒绝分开报告）。用户取消本轮不算拒绝。
- 显式 `ask` 规则（全局或项目规则）、工作区外的删除和移动、`approval: "never"` 不交给审查，仍按宿主机受限处理；敏感目标拒绝和外部覆盖拒绝照旧在审查之前生效。
- 连续 3 次拒绝，或最近 50 次审查中拒绝 10 次，即熔断：之后的审批改为询问用户，状态栏显示“Auto 已暂停”。用户在询问中允许一次操作（含“允许，并在本项目不再询问”）后，计数清零，恢复 Auto 审查（参照 Claude Code）。重新选择 `/permissions` 同样会重置。
- `/permissions auto` 列出最近 10 次 Auto 拒绝（参照 Codex 的 `/approve`）。用户选中一条后，模型下次以完全相同的形式发起这次调用时会再审查一次，并告诉审查模型用户已允许重试；只生效一次，本身不等于批准。
- 批准只对这一次调用有效，不写入项目规则，也不在会话内复用。每次审查调用一次当前模型，会产生费用；批准和拒绝都以通知显示给用户。

一次授权绑定原工具、原参数、当前会话和权限代次；切换后不能复用。用户拒绝保留在当前会话历史，写回时使用稳定的候选内容和版本作为拒绝身份，不因重新生成原生 revision ID 而再次获准。

搜索路径默认是工作区根目录。子目录的 `deny` / `ask` 同样约束覆盖该目录的搜索；限定子目录的 `allow` 不扩大为整个工作区授权。路径规则和目标均解析实际目录身份，目录别名不能绕过规则。宿主模式的 `lsp_fix(write: true)` 属于变更，授权绑定 `root` 与 `path` 对应的文件，并受 Plan、受保护路径和权限撤销约束；预览不取得写入授权。

宿主读取和搜索使用工具自身的路径规范化规则，授权后执行绑定已核准的实际路径，`@`、`~` 或文件名兼容拼写不能指向另一授权对象。原生写入/编辑按各自的路径规则检查，包括批次内每一项。沙箱搜索支持 `src`、`./src` 和 `src/example.txt`，目录范围不误匹配 `src-other`。

宿主模式为子代理、结构化只读命令及浏览器执行签发当前调用的凭证；子代理逐项绑定工作区身份和读写能力，结构化命令绑定 cwd、参数及精确外部根。路径规则先于凭证签发生效，权限切换撤销未完成调用。Plan 中子代理降为只读，浏览器代码执行被拒绝。这些扩展没有沙箱后端，在前两档仍明确返回不支持。

宿主模式仍属于受信任执行。扩展初始化、provider 与应用自己的会话持久化运行在宿主；沙箱隔离的是已接入的文件/命令工具执行，不把整个插件进程宣称为 VM 内运行。

## “离线”与启动的关系

`superpi` 是日常启动命令。已有构建可直接运行，不需要另选“离线版”或“沙箱版”。`npm run build:offline` 只是维护者的构建命令，使用本地模型目录数据；`superpi --offline` 仅跳过启动时的更新、目录刷新等网络操作。它们都不选择权限模式，也不会把远程模型变成本地模型。

实现、实机验收与性能证据见[总进度记录](Super%20Pi%20权限简化与原生能力整合方案.md)和[性能检查](performance/native-sandbox-closeout-2026-11-03.md)。旧失败、停止与旧任务协议的记录保留为历史证据；当前交互行为以本页为准。
