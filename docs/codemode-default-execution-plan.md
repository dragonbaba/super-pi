## 默认行为与调用边界

普通工具默认通过 Codemode 调用，必要的交互、Plan/Goal 完成等控制工具保持直接暴露。可发现、向模型展示和允许调用是三个不同概念。已配置的 MCP 工具在默认切换时必须继续可用。

TUI、打印、JSON/RPC 和 `createAgentSession()` 采用一致默认值。已有会话缺少新字段时采用默认。`--no-tools`、显式工具白名单、Plan mode 以及策略禁用继续生效，搜索结果不能扩大权限。模型不支持专用代码格式时，使用 JSON 代码参数进入同一运行时。

每个嵌套调用复用参数校验、工作目录解析、权限、资源保护、编辑证据、事件、输出预算及取消链。失败不能触发隐式直连 Shell 降级，非幂等调用不能自动重试。工具目录变化或等待审批后，执行前重查当前授权状态。

当前 `Agent.dispatchHostTool()` 会拒绝运行中的 Agent，因此嵌套调用必须接入当前运行的调度链，不能递归调用该入口，也不能直接调用工具实现绕过检查。父级编排不能占住子调用需要的串行执行锁。

## Shell 失败样例与处理原则

| 样例 | 已有证据 | 实施原则 |
| --- | --- | --- |
| `cd /d; find ... -o ...` 被拒 | 独立 cd 后的只读尾部检查不接受 find 的 -o；Git Bash 的 /d 会切到 D 盘根目录 | 明确支持安全的 find 逻辑组合；优先使用调用的 cwd；测试不能删除写入选项保护 |
| grep 退出 1 | 可能是无匹配，历史输出不足以确认其他原因 | 结构化搜索可报 no_matches；混合 Shell 保留真实退出码 |
| 多命令结尾搜索退出 1 | 最后命令可决定脚本退出码 | 不把“执行失败”和“从未执行”混为一谈，不给任意脚本追加成功退出 |
| Bash 包装 PowerShell 被拒 | 包装器规则拒绝该路径 | 使用原生 PowerShell 工具；不得隐式改变授权或 shell 语义 |
| nw.exe --version 超时 | 实际执行超时；没有证据证明解析错误 | 优先查询文件版本；head 不保证终止无输出进程；测试不启动游戏 GUI |

解析检查限定在可证明的风险与策略事实。不要通过无限增长的正则分支尝试证明任意脚本语义，也不要全局关闭资源保护。

## 结果与编辑证据

宿主维护可信的父子调用 ID、结果状态和来源。脚本捕获异常或输出“完成”不能抹去失败、未知状态或已经发生的副作用。脚本状态与业务工具状态分别记录。

脚本内部读取可用于计算，但只有实际展示给模型的可信读取内容，才可在后续完成的轮次中成为编辑证据。截断只授权可见范围。来源信息由宿主持有，不信任经 VM JSON 传回的路径、哈希或伪造字段。同一模型轮次内的读取和修改不自动满足现有保护。

会话存储有容量限制、版本和分支归属。权限结论不写入存储。分支切换、重载、压缩时处理失效，避免每次脚本重放整段历史。脚本存储事务不会回滚外部工具已产生的副作用。

## 资源与并发初始约束

以下为初始设计值，修改必须记录理由和测量，不能静默取消限制：每会话一个活动 Codemode 执行；可信只读子调用并发不超过 4；写入和状态修改串行；每脚本最多 256 次子调用；禁止递归 Codemode。未知 MCP 的自报只读标记不能作为并行授权。

输出预算覆盖 VM 发出消息之前、Worker 队列、宿主累计和模型展示四个边界。大结果复用现有文件化与恢复机制。队列、脚本输入、VM 内存、消息体、累计输出及会话存储都有显式上限和失败诊断。

保留每执行独立 Worker 的可终止性；复用已编译 WASM 和按工具目录版本缓存的静态描述。首轮不引入 Worker 池或对象池。终止会释放逻辑引用，同时真实外部工具的完成或取消状态仍须记录。

## 性能写法

完整遵守 [热路径分配契约](performance/hot-path-allocation-contract.md)，检查从生产者到释放边界的完整调用链。

| 项目 | 规则 |
| --- | --- |
| 闭包 | 增量、进度、事件、渲染循环零内联闭包、零 Promise 回调尾链、零逐事件 bind；稳定回调在模块或实例生命周期创建一次 |
| 动态正则 | 固定正则放常量；动态模式在配置版本变化时编译并限制缓存；热路径禁止 new RegExp 和 RegExp 调用；不共享有 g/y 可变状态的表达式 |
| 常量模块 | 放不可变协议值、表、schema、正则和默认值；不放当前会话、权限结论、参数结果或共享可变 scratch |
| 可复用状态 | 实例或调用拥有，容量有界，finally 清除引用；不覆盖异步使用者持有的对象，超大 backing store 不长期保留 |
| 字符串 | 热路径避免 new String 和 String 调用；禁止用隐式转换掩盖完整帧复制；不要完整序列化大参数只为生成短预览 |
| 对象数组 | 稳定字段和索引循环；避免每次更新复制整段调用记录；快照仅在真实交付边界生成，保留外部观察者隔离 |
| Promise 与取消 | 正常进度和帧零 Promise、AbortController 及 options 包装分配；执行级创建按生命周期计数并回收 |
| 大结果 | 先限制再跨桥；增量累计；不先完整 join/split 再截断，不为估算复制整个结果 |

这些规则约束宿主热路径，不禁止用户脚本正常使用 JavaScript 语法。对象池须先有 profiler 证据，并满足契约中的所有权、容量、清理、测试和收益门槛。

## 验证与交付检查

- 功能：默认入口、只读及写入、限制模式、白名单、MCP、会话恢复、两类代码参数格式。
- 故障：嵌套拒绝、目录变化、部分成功、捕获异常、死循环、洪泛、超时、取消、未等待调用。
- 证据：隐藏、同轮、过期、截断、伪造读取，以及分支切换。
- 结构：相关 AST/source invariants；零逐进度闭包/Promise/包装对象；帧 activeWrite ≤ 1、pendingLatestFrame ≤ 1、queue HWM ≤ 2。
- 测量：无调用启动、首次/后续脚本、单读/批量读/串行写、大工具目录、10 MiB 单行、频繁进度；区分固定沙箱成本和子调用增量成本。
- 生命周期：成功、错误、取消、销毁后的 Worker、监听器、定时器、挂起调用和引用释放；受控 GC 与重复周期无无界增长。
- 最终：按 [测试说明](testing.md) 执行类型检查、离线构建、完整测试及相关分配基准。平台未执行必须说明，不以当前 Windows 结果替代 Linux 验证。
- PR 前检查：每组文件映射、实际 diff、边界及错误处理、生成物与打包、临时诊断、测试发现、基准对照、许可证、意外文件和未解决问题。

“建议 p95 回退不超过 5%”是相同环境下未改动热路径的目标，不是已经测得的结果。新跨沙箱调用单独测量固定成本，不伪称与原生直调无差别。
