# 命令识别与权限分级第二轮计划

日期：2026-11-06。前置：PR #246（PowerShell 反斜杠路径）已合并；#247（MCP destructiveHint 询问与服务器规则）、#248（PowerShell 文件 cmdlet 与 `cmd /c`）在审。

## 1. 授权与约束

- 用户在 2026-11-06 明确要求：“指令识别，沙箱和非沙箱都挺落后的，还需要优化，性能这块也要看，存储数据结构等”。本计划是对《宿主机权限与子代理修复计划》第 7 条（禁止加强命令预检）的**限定范围解除**，范围以本文第 4 节列出的 PR 为准；范围之外仍按第 7 条执行。
- 威胁模型不变：防止模型误操作，不是对抗性安全边界。不追求防绕过矩阵；识别遗漏如实记为边界。测试只要代表性用例，不做变体×语言×模式矩阵。
- 用户已确认的决策（2026-11-06）：
  1. **权限分级补一档“宿主机受限”**，与“宿主机完全权限”并列，补齐后与 Claude Code、Codex 的分级对齐。Auto 模式放在“宿主机受限”之内，实现方式待 R6 前单独确认。
  2. **“以后不再询问”持久化**：不能只放内存；类似 Claude Code，但按**项目文件夹共享**，用户可以随时修改。
  3. **沙箱不提供“沙箱外重跑”**。路径受限而失败时立即停止并告知用户，由用户自己扩展工作区（`/add-dir`）；网络需求单独询问并征求同意。两者分开处理。
  4. **Plan 模式放开只读命令**。
  5. 实施方式：先提交本计划，再按顺序逐个提 PR，每个 PR 按老规矩通过 6 个 CI 分片和 Codex 审查后合并。
- 继续适用：热路径分配契约（shell 授权不在其热路径清单内，但同样遵守：预先建表、不在循环中建闭包、不用临时包装对象和数组）；task-tmp 规则；验证原始数据放 `.task-tmp`，文档只留摘要。

## 2. 现状（实测）

### 2.1 沙箱模式（只读 / 沙箱读写）

- 原生授权在沙箱模式下**不做任何命令识别**，隔离完全依赖 Windows Sandbox 的挂载：只读快照、可写副本、默认禁网。
- 命令引用工作区外的宿主路径时，只会在 VM 内报“找不到”，模型看不出原因，常见的反应是反复重试或换写法。
- 禁网时 `npm install`、`git clone`、`curl` 失败，模型同样看不出是网络被禁。要开网只能改全局 `sandboxNetwork` 再 `/reload`，过程中没有询问。

### 2.2 宿主机模式（全部读写）

- 每条命令先后经过三套扫描：`inspectHighRiskBashMutation`（core.ts，2149 行，自带 `parseShellSegments`）、`inspectBashPermissionScope`（permission-bash.ts，经 `analyzeShellSource`），PowerShell 还要再经过 `powershell-policy.ts`（自带分段和分词）。plan-mode 另有第四套 `splitShellSegments`。
- 上一轮的两个缺陷都出在这些解析器之间的语义差异上：PowerShell 的反斜杠被当作转义，`cmd /c` 只取后面一个词。#246 和 #248 是在入口处改写路径分隔符来规避，没有统一词法。
- 规则只支持“工具 + 完整命令精确匹配”。审批只有“允许一次 / 拒绝 / 拒绝并说明原因”，没有“以后不再询问”，也没有命令前缀规则。
- 宿主机只有一档：除已识别的工作区外删除、外部覆盖和敏感目标以外一律放行。没有“读命令自动、其他命令询问”的受限档。
- Plan 模式下，原生授权直接拒绝所有 bash/powershell（`execution-policy.ts` 的 plan 分支），plan-mode 扩展自带的只读白名单实际不起作用。

### 2.3 性能与数据结构

单次 `inspectNativeShellMutations` 的耗时（本机，同一进程预热后取平均；原始数据在 `.task-tmp`，不入库）：

| 命令 | 长度 | 耗时 | 其中 core / scope |
| --- | --- | --- | --- |
| `ls -la` | 6 | 5.0 µs | 1.8 / 1.5 µs |
| `rg … \| head \| sort \| uniq -c` | 43 | 9.7 µs | 4.7 / 4.7 µs |
| `cd … && npm test … 2>&1 \| tail` | 58 | 15.5 µs | 4.7 / 6.0 µs |
| 60 行脚本 | 3,389 | 0.46 ms | 0.15 / 0.22 ms |
| 960 行脚本 | 57,269 | 4.5 ms | — |

完整 `authorize`（宿主机）：读和搜索约 0.12 ms，写约 0.38 ms，`rm -rf dist` 约 0.72 ms，主要花在 realpath、home 和系统根目录等文件系统调用上。

结论：耗时随长度线性增长，相比进程启动可以忽略，**性能不是用户可见的瓶颈**。真正的问题在结构上：

- 同一条命令被解析两到三次。core 和 scope 各占一半耗时，而且各自对语法的理解可能不一致。
- `ShellSegment` 是一个 `string[]`，上面最多挂 17 个可选属性（`expansions`、`redirections`、`firstWordQuoted` 等）。每个分段都会派生出不同的隐藏类，还要另建若干平行数组。
- `ShellAnalysisOwner` 用完整源文本作为 Map 的键来缓存分析结果。嵌套脚本较多时，键和值都会保留整段源文本。
- builder 里的目标和原语用数组加线性 `includes` 去重，上限是 16。这在当前规模下没有问题，但需要保持上限。

本轮的性能目标因此是**结构性**的：每条命令只解析一次，换成紧凑的 token 存储，用确定性计数器作为回归门槛。不宣称速度提升，速度只作为附带结果记录。

## 4. PR 顺序

各 PR 串行推进，前一个合并后再开下一个。每个 PR 只附代表性测试，并在本文第 5 节补一条完成记录。

### R1 统一 Shell 词法层

- 新建 `shell-policy/syntax/`，为 bash、PowerShell、cmd 各写一个分词器，产出同一种 token 表：
  - 源文本只保留一份；
  - 每个 token 用 `Uint32Array` 记录起止偏移，用 `Uint8Array` 记录标志（引号、展开、重定向、文件描述符等）；
  - 另有一张分段表，记录分隔符、管道、条件和子 shell 深度。
  - 词文本按需切片，不预先物化 `string[]`。
- core 的高风险扫描、permission scope、原生目标收集、PowerShell 只读判定和 plan-mode 安全判定都改为消费这张表。删除 #246 和 #248 的分隔符改写，改由 PowerShell 和 cmd 分词器直接把 `\` 当作分隔符。
- 行为保持不变。验收：
  - 现有套件全部通过；
  - 新增一个差分测试，覆盖代表性命令语料（现有测试里的命令加上第 2 节的探针），断言新旧实现的目标、类别和不确定标志一致；有意修正的差异逐条列出。
- 计数器门槛：每条命令每种方言解析次数 = 1；每个分段的包装对象 = 0；分析结束后 owner 释放全部引用。耗时只作记录。
- 规模较大时拆成 R1a（PowerShell 和 cmd）、R1b（bash，同时供 core 和 scope 使用）。

### R2 统一只读命令判定，Plan 模式放开只读命令

- 只读清单按 Claude Code 的口径建立，PowerShell 一并覆盖：
  - 通用命令：ls、cat、echo、pwd、head、tail、grep/rg、wc、which、diff、stat、du、cd、sort（不带 `-o`）、find（不带 `-delete`/`-exec`/`-fprint`）；
  - 只读 git：status、diff、log、show、ls-files、rev-parse、blame、`branch --list`；
  - PowerShell：沿用 `Get-*` 读集合。
- 清单和判定都基于 R1 的 token 表，取代 `powershell-policy.ts` 和 plan-mode 的 `findBlockedCommandSegment` 两套实现。plan-mode 的 `safeSubcommands` 配置保留。
- Plan 模式在所有环境下只放行判定为只读的命令；写入类命令和无法判定的命令仍然拒绝，并在提示中说明原因。

### R3 权限分级：增加“宿主机受限”

- `/permissions` 的四档：只读（沙箱）/ 沙箱读写（默认）/ **宿主机受限** / 宿主机完全权限（即现在的“全部读写”）。新会话的默认值不变。
- 宿主机受限的语义参照 Claude Code 的 default 加 acceptEdits：
  - 自动执行：工作区（含 `/add-dir`）内的文件工具操作；R2 判定的只读命令；已识别且所有目标都在工作区内的文件命令（mkdir、touch、rm、mv、cp、Set-Content 等）。
  - 询问：其余 shell 命令、MCP 调用、工作区外的读写。
  - 拒绝：沿用现有的敏感目标拒绝和外部覆盖拒绝。
- 宿主机完全权限保持现状。会话模式记录、迁移和状态栏随之扩展；旧记录里的 `host-write` 映射为“宿主机完全权限”。

### R4 项目共享的规则与“以后不再询问”

- **存储位置**：`~/.sp/agent/projects/<规范化项目路径的哈希>/permissions.json`，同时记录原始路径以便辨认。
  - 按项目文件夹共享，所有会话都读同一份。
  - 放在用户目录下，克隆来的仓库无法夹带授权。
  - 用户可以直接编辑，也可以用 `/permissions rules` 打开。
  - 如果希望文件放在仓库内（`.sp/permissions.local.json`），需另行确认，因为那样需要处理“来源仓库自带授权”的信任问题。
- **规则语法**沿用 `{tool, decision, command}`：`command` 支持 Claude Code 风格的 `*` 通配（`npm test *`、`git log *`），按词边界匹配。
  - 复合命令的每个子命令都必须被允许；任一子命令命中 deny 或 ask 即生效；优先级 deny > ask > allow。
  - 规则加载时按首词建索引（`Map<首词, 规则[]>`），匹配时不分配内存。
- **热更新**：每次授权前检查文件的 mtime 和大小；有变化才重新解析，解析失败时保留上一版并提示，不放宽。
- **审批对话框**增加“允许，并在本项目不再询问”。保存内容是本次需要审批的各子命令的前缀规则，最多 5 条，与 Claude Code 一致。
  - 只在宿主机受限和沙箱模式下提供。宿主机完全权限本来就不询问普通命令。
  - 敏感目标拒绝、外部覆盖拒绝和工作区外删除不能靠这条“不再询问”跳过，每次都要确认。

### R5 沙箱命令识别：停止与网络询问分开处理

- **执行前**：用 R1 的 token 表识别命令中指向“未映射宿主路径”的静态绝对路径，例如工作区外的 `D:\other\x`。命中则不执行，暂停本轮任务并告知用户：哪个路径不在沙箱工作区内，可以用 `/add-dir` 添加。不自动扩大工作区，也不提供沙箱外执行。
- **执行后**：结合失败输出和命令中识别出的路径，判断属于路径类失败（未映射、只读挂载写入）还是网络类失败（DNS 解析失败、连接被拒，同时命令属于常见联网命令），在结果中写明原因，让模型停止而不是反复重试；路径类同样暂停并告知用户。
- **网络询问**：禁网时识别到常见联网命令（npm/pnpm/yarn install、pip install、git clone/fetch/pull/push、curl、wget 等），执行前单独询问“本会话是否允许沙箱联网”。
  - 同意后，以会话级覆盖重建 VM 并开网，状态栏显示已联网；拒绝则不执行并告知。
  - 全局 `sandboxNetwork` 仍然是默认值；项目配置仍然不能开网。
  - 识别遗漏的联网命令按现有行为在禁网下失败，并由执行后的分类说明原因。

### R6 Auto 模式（宿主机受限内）

- 草案参照 Codex 的 auto_review：
  - 只审查本来会询问用户的动作，由审查模型给出批准或拒绝；
  - 审查模型看到精简的对话记录和完整请求，不包括隐藏推理；
  - 构建失败、超时、解析失败一律按拒绝处理；
  - 连续 3 次拒绝，或最近 50 次审查中 10 次拒绝，则熔断并回到人工询问；
  - deny/ask 规则、敏感目标拒绝、外部覆盖拒绝和工作区外删除不经过审查。
- 审查用哪个模型、成本和上下文边界，在开工前与用户单独确认，本计划不预设。

### R7 宿主机识别补全（小）

- 按“常见正常写法”的标准补以下几项：
  - PowerShell 的 `Set-Location`/`cd` 之后，后续相对路径的 cwd 跟踪；
  - `git -C <dir> clean|reset --hard` 的目录；
  - `git worktree remove`；
  - `rsync --delete` 的目标；
  - `tar -C` 解压的目标目录。
- 仍不识别：.NET 方法调用、`npm cache clean`、非字面的参数展开，继续记为边界。

- **R1b：Bash 分词器**
  - 范围：
    - 新增 `syntax/bash.ts`，取代 core `parseShellSegments` 和 permission `inspectScript` 各自的一份字符循环。规则逐条移植自 core：引号、转义和续行、简单 `$'...'`、词内的 `$(...)`、`((`/`$((`、`[[ ]]`、注释、带源描述符的重定向，以及列表、管道和子 shell 分隔符。
    - token 表增加 Bash 字段：解码后的词文本和描述符文本各存一份；分段表增加源偏移、管道/条件/子 shell 关闭/动态标志，以及 `[[` 与 `((` 的位置。

    - permission scope 每个脚本只用一个词缓冲，按分段填入。core 的辅助函数需要跨分段读取，并且会原地剥离重定向，所以每次调用仍拿到新的分段数组，词字符串来自表，不再逐字符拼接。把 core 改成直接读表留待以后。
    - 统一后，两处细节改用 core 的口径：permission 中裸 `$x` 的展开位从 1 改为 2；`[[ ]]` 内部，以及 `[` 后面紧跟 `[` 或空白时，不再标为通配。两处都不改变判定。
    - 修正：`&&`/`||` 之后分段的源起点原先落在运算符的第二个字符上，现在落在整个运算符之后。只用于同一张表内的偏移比较，结果不变。
    - 修正：脚本结尾不再把前一个 `)` 分隔符改写为“无”。
  - 差分：从 shell-policy 和 guard 相关测试里收集了 3369 条字符串，与 main 对比原生目标、permission scope、高风险扫描、生命周期（两种 PowerShell 可用性），以及状态、存储脚本、进程源、循环头四个辅助函数的结果。3369 条全部一致。
  - 计数：
    - 有 owner 时，每个 Bash 源分词 1 次。测试中三个扫描器读两个源，计数为 2；无 owner 时同一组调用超过 6 次。
    - 授权结束后 owner 释放全部表，`liveOwners`、`liveEntries`、`liveBytes` 回到基线。
    - 分词器内没有闭包、字面量或临时容器；`[[` 判断用的词表是模块级可复用缓冲，返回前清空。
    - 耗时（仅记录，同一 owner 依次跑生命周期、高风险、scope 三个扫描器）：三条代表命令分别从 5.6、11.9、30.7 µs/op 变为 5.5、10.8、27.8 µs/op；原生授权从 5.0、9.6、25.5 变为 5.1、9.0、23.3。不经 owner 单独调用辅助函数会变慢（每次都要建表），生产路径都经过 owner。
- **R2：统一只读命令判定，Plan 模式放开只读命令**
  - 范围：
    - 新增 `shell-policy/readonly-command.ts`：`findNonReadOnlyShellSegment` 读 R1 的 Bash 和 PowerShell token 表，返回第一个非只读分段的原文。它取代了 `utils/powershell-policy.ts` 和 plan-mode 自带的分段、分词与参数校验。旧名 `findUnsafePowerShellSegment` 保留为兼容导出。
    - 原生授权的 Plan 分支不再拒绝所有 bash/powershell：只读命令放行，其余拒绝并写明是哪一段。plan-mode 扩展用同一个判定。
    - plan-mode 的 `safeSubcommands` 配置保留，通过 execution owner 的 `readOnlyShellSubcommands()` 传给原生授权，两边口径一致。
    - PowerShell permission scope 改用同一判定，传入 owner，与原生扫描共用同一张表。
  - 判定规则：每个分段都必须是清单里的读命令，分段之间只能用 `;`、`|`、`&&`、`||` 或换行连接。以下情况一律不算只读：变量、命令替换、`$(...)`/`@(...)`、脚本块、子 shell、后台作业、前置 `NAME=` 赋值、未知程序，以及写文件的重定向。
  - 有意放宽（相对旧的 plan-mode 白名单）：
    - 去掉了对所有命令统一禁止 `-i` 的规则，所以 `grep -i`、`rg -i` 可用；`sed -i` 和 `tsc -i`（即 `--incremental`）仍然禁止。
    - 只拒绝命令前面的 `NAME=` 赋值，参数里的 `a=b` 不再拒绝。
    - Bash 参数允许 glob 和 `~`，但 `uniq` 的参数里不允许 glob，因为展开后可能多出第二个操作数，也就是它要写的文件。`{a,b}` 仍然拒绝：展开后的选项和操作数无法校验，例如 `find . -{print,delete}`。
    - 允许 `2>&1`、`>/dev/null`、`>$null` 和 Bash 的 `< file`。
    - 允许用换行分隔多条命令。
    - `git rev-parse`、`git blame` 改为内置只读；`git branch --list <pattern>` 可用。
    - PowerShell 可以使用共享清单中的外部命令（如 `git status`、`rg`）；新增 Select-Object、Where-Object、cd/Set-Location 和 Get-Command。
  - 计数与契约：
    - 有 owner 时，PowerShell scope 和只读判定共用一张表。测试断言 2 次判定只分词 1 次，owner 释放后 size 为 0。
    - 新文件的所有函数都加入了 source invariant：没有回调、Promise 或 Buffer 复制。参数检查用循环，不用 `some` 闭包；常量表在模块级预先建好。
  - 边界：
    - 只做误操作防护。glob 展开成以 `-` 开头的文件名、经别名改写的命令等情况不做防护。
    - Bash heredoc 一律不算只读。
    - 显式写成 `.exe` 的程序（如 `sort.exe`）不在清单内。`git branch` 按选项出现的顺序处理 `--list`/`--no-list`。
- **R3：权限分级增加“宿主机受限”**
  - 范围：
    - `permission-mode.ts` 增加 `host-restricted`、四档顺序 `PERMISSION_MODES` 和 `isHostPermissionMode`。两个宿主档都走 trusted-host 后端；原先写死 `=== "host-write"` 的后端判断（设置、会话、运行时校验、授权构造）改用该函数。
    - `host-write` 的显示名改为“宿主机完全权限”，含义不变，旧会话记录无需迁移。新会话默认值不变，两个宿主档都不会成为新会话默认。
    - `/permissions` 列出四档；两个宿主档切换前各有一次确认，提示各自的行为。
  - 判定（在显式规则之下，规则仍优先）：
    - 工作区外的路径：`paths()` 在宿主档不再抛错，标记 `outside`；受限档对此询问。覆盖读、搜索、文件工具、shell 识别出的目标，以及委派给子代理或结构化只读命令的工作目录。
    - shell：新增 `classifyHostShellCommand`，与 R2 共用分段判定。全部分段是读命令时直接执行；全部分段是读命令或清单中的文件命令（Bash：rm、rmdir、mkdir、touch、cp、mv；PowerShell：Remove-Item、New-Item、Set-Content、Add-Content、Clear-Content、Out-File、Copy-Item、Move-Item、Rename-Item 及其别名），操作数都是字面量，Bash 文件命令只带清单内的选项（如 `-rf`、`-p`、`--`；`cp -t`、`--target-directory`、`-b`、`-S`、`-l`、`-s`、`touch -r`、会一并删除上级目录的 `rmdir -p` 等改变或增加写入位置的选项不在清单内），并且原生变更分析给出的目标确定、都在工作区内时，直接执行。读命令写到字面路径的 `>`/`>>` 也算文件命令。其余询问。
    - MCP 工具默认询问；指明工具或服务器的 `allow` 规则可免去询问。
    - PowerShell 中，位置切换（cd、chdir、Set-Location、sl）之后的文件命令询问，因为变更分析只按起始位置解析目标；`New-Item` 只允许 `-ItemType File/Directory`，链接和联接会让同一条命令里后面的写入改道。
    - 识别出的写入目标是已有目录时询问：`cp a.txt dir`、`Copy-Item a.txt dir` 实际写入 `dir` 下的子项，子项可能是指向工作区外的链接。代价是 `mkdir -p` 已有目录也会询问。
    - 敏感目标拒绝和外部已有文件覆盖拒绝照旧，先于询问生效。
  - 计数与契约：
    - 受限档在授权里建一个 analysis owner，原生变更分析和命令分类共用它。测试断言一次 PowerShell 授权只分词 1 次，与完全权限档相同；授权后 owner 全部释放。
    - 新函数加入 source invariant；文件命令清单是模块级常量。
    - 核对过清单中每个命令名单独使用时，原生分析都能给出目标或标记为不确定（不确定即询问），不会出现“分类为文件命令、但目标没被检查”的情况。
  - 边界：
    - 只读命令不提取路径，所以 `cat` 读工作区外的文件不询问。这一点与计划一致（“R2 判定的只读命令”直接执行），按误操作防护的威胁模型接受。
    - `cp` 的来源路径是读取，不计入工作区检查。
    - 自定义扩展工具和 browser_exec 在受限档仍按现有默认允许。
    - 用户附加的输入文件和变更观察（`authorizeFileObservation`）不是模型的工具调用，仍按已有授权处理，不询问。
    - 子代理继承受限档。子进程没有交互界面，需要询问的调用以 `APPROVAL_REQUIRED` 失败，不会被默默放行。
    - 原生扫描器只看前 64 个分段，超过时分类直接归为“其他”。permission 扫描在超限时把已识别的变更标为不可核实，因此完全权限档的外部覆盖检查也不再漏掉后面的分段。
    - 目标在执行前就已解析，因此同一条命令中 cp/mv（及 PowerShell 的复制、移动、改名）之后不能再跟文件命令，否则询问：复制或移动可能把已有的外链带到新路径（`cp -r` 会保留目录里的链接），后面的写入会顺着它出去。`cp -a` 也不在允许的选项内。
- **R4：项目共享的规则与“不再询问”**
  - 范围：
    - 新增 `project-permissions.ts`：规则文件在 `<agentDir>/projects/<规范化项目路径 sha256 前 32 位>/permissions.json`，记录原始路径；Windows 先转小写再取哈希。
    - 每次授权前 `lstat` 一次，mtime 或大小变化才重新解析；解析失败保留上一版并提示一次。重新加载期间到来的授权共用同一次加载，版本号在规则解析完成后才更新，不会读到旧规则。写入走临时文件加 rename，追加时去重，总数上限 256。
    - 保存（Codex 审查后补）：同项目的会话用 `permissions.lock` 串行保存（崩溃遗留的锁 10 秒后失效）；替换前再 `lstat` 一次，发现手动编辑就重新合并；写入前按读取时的限制校验整个文件和大小，生成的前缀规则不超过单条长度上限。
    - `/permissions rules` 显示文件位置和规则；`/permissions` 的提示和斜杠命令说明同步更新。
  - 判定：
    - 规则在加载时编译：shell 规则按首词建 `Map<首词, 规则[]>`，首词含 `*` 的单独列出；其他工具按名称存最强决定。匹配用双指针通配算法，按词匹配，不分配内存（PowerShell 查首词时转一次小写）。
    - 不写 `command` 的规则按整个工具记录，与命令能否解析无关（`FOO=$(git push)` 这类没有命令词的分段也受约束）；`file_batch` 的每项操作也按各自工具名取项目规则。`/changes` 核对当前状态用的 `authorizeFileObservation` 也查项目的 `read` 规则，`deny` 和 `ask` 都阻止（没有对话框）。PowerShell 的大小写折叠在规则和命令两侧逐个 UTF-16 字符进行，非 ASCII 字母一致。
    - `deny`/`ask` 在所有档位生效：宿主档复用变更分析的 token 表，沙箱档单独分词一次。词按原文比较，跳过 Bash 开头的变量赋值和控制结构关键字（if、then、else、elif、do、while、until、!、{、time），PowerShell 的分段保留脚本块，未加引号的大括号（包括紧贴单词的 `{git`、`main}`）把块内命令分开逐条匹配，并跳过 try、catch、finally、if、elseif、else、do、while、foreach、switch 等关键字（不区分大小写）和点号调用，所以 `git push *` 也匹配 `FOO=1 git push $REMOTE` 和 `if …; then git push; fi`。Bash 的 deny/ask 在原始命令上屏蔽 heredoc 正文后匹配（正文里的引号不会吞掉结束符之后的命令；不用变更分析的视图，它会把 `node <<EOF` 改写成 `node -e …`），heredoc 无法定界且存在 deny/ask 规则时询问；含 `<<` 的 Bash 命令不参与 allow，也不生成前缀建议。以这些关键字开头的分段不能被 allow 规则放行，也不提供“不再询问”。
    - `allow` 进入宿主机受限的分类：被拒绝的分段若是顶层字面量简单命令并命中 allow，整条命令归为 `HOST_SHELL_RULE_ALLOWED`，只要变更分析没有标记不确定就直接执行。之后的文件命令按“已移动”处理并询问；被规则允许、但带文件重定向的分段若出现在这类命令之后，同样询问。MCP 工具命中 allow 时免去受限档询问和破坏性注解询问。
    - “不再询问”只在询问可以被规则免去时提供：受限档、目标都在工作区内、分类为“其他”或 MCP、没有不确定目标或写入已有目录（保存规则后这些仍会询问）、没有命中 `ask` 规则，并且显式规则在允许兜底下也是允许。前缀规则取首词和第二个非选项词加 ` *`，最多 5 条，超过或含动态词时不提供。保存失败时提示，本次仍按允许执行。
  - 计数与契约：
    - 规则匹配和新增的分段函数加入 source invariant。测试断言带规则的一次 PowerShell 授权只分词 1 次，共享的 owner 释放后 size 为 0。
  - 边界：
    - Bash 的 deny/ask 同时匹配常见分派前缀之后的命令：command、builtin、exec、sudo、doas、env、nohup、nice、timeout（各前缀按自己的选项表跳过选项和值；`command` 的选项里出现 -v 或 -V 只是查询，按原样匹配）。
    - `$(...)` 内部的命令不参与规则匹配；别名、变量里的命令名和 `Invoke-Expression` 字符串同样不展开，按威胁模型记为边界。
    - 含脚本块的 PowerShell 分段（`ForEach-Object { … }`）不参与 allow，也不生成前缀建议。
    - 沙箱两档目前只有显式 `ask` 规则会询问，所以“不再询问”暂时只出现在宿主机受限档；R5 的网络询问会复用它。
    - 宿主机完全权限本来就不询问普通命令，`allow` 在该档没有作用。
